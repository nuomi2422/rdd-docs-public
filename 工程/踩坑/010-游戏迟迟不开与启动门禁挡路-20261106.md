# 游戏迟迟开不起来：启动脚本被 preflight 挡了，而报错没人看（2026-11-06）

## 现象

主干活多次说“要开窗验证”，但游戏进程始终没起来；外部只看到“卡住/没开”，没有任何显式错误。当天已经发生过数次（主人指出“这是个毛病，已经出现过几次”）。

## 原因（实测，非推断）

`[内部路径已省略]` 是唯一启动入口，它在起游戏前有两道硬门：

1. **审计门**：`[内部路径已省略]` 存在 → 打印 `REFUSED: audit gate pending` 并 `exit 2`。本次该文件不存在，不是它。
2. **preflight 门**：`harness-gate.js preflight` 非 0 → 打印 `REFUSED: preflight BLOCK` 并 `exit 3`。**本次就是它**：
   - `P14 工作区干净（含 untracked）`：docs 仓 11 处未提交（含未跟踪的 043 与外部学习决策卡）+ harness 仓 2 处（`bin/code-gate.js`、`registry.json`）；
   - `P9 时间锁未到期`：`TL-2026-10-06-01`（dev jar 缺 lang）复核日 2026-11-06 已到。

两道门都在**启动前**、且都以文本输出 + 非零退出码结束；如果启动是由后台脚本/pipe 拉起，输出被丢弃 ⇒ 外面只看到“游戏没开”。

## 修法（本次已做）

1. 把待提交文档与门禁脚本改动**精确提交**（docs 仓 `4bc0c72`；harness 仓 `4a98a06`），P14 转 PASS。
2. `TL-2026-10-06-01` 复核：**guard 当前是红的**（`check-jar-lang.js` 对部署的 api jar 报缺 lang JSON，exit 1），因此**没有静默续期成功**，而是按锁规则显式续期一周到 2026-11-13，并在 registry 里写明“guard 红、修法是先跑 runData 再重建 api jar”。
3. 复核结果：`preflight` → `PASS=12 WARN=4 BLOCK=0`，`VERDICT=PASS`，启动门恢复。

## 为什么反复发生（该记住的）

- **启动失败是“静默”的**：`start-rdd.ps1` 输出 REFUSED 后退出，进程表里什么都没有，看起来和“游戏卡了/没开”一模一样。
- 门禁的设计本意是好的（脏工作区不许开新批次、到期锁不许混过去），但它把**失败信号留在 stdout**，而调用方常是后台启动/pipe，stdout 被吞。
- 同族坑：TL-2026-10-08-04（`Start-Process -ArgumentList` 数组含空格路径 → 静默失败，只看到“没反应”）。**“没反应”必须先查启动脚本的门禁输出，不要先怀疑游戏。**

## 下次的判据（写死，不要凭记忆）

1. 游戏没起来时，先跑：`node [内部路径已省略] preflight`，看 `VERDICT` 与 `BLOCK` 项——**不要先怀疑 MC 本体**。
2. 再查 `AUDIT-REQUIRED.json` 是否存在。
3. 两道门都过了仍不起，才去看 `mc-launch.mjs` / 日志。

## 遗留（未修，别当已修）

- **api jar 缺 lang JSON（TL-2026-10-06-01 的 guard 仍红）**：需要跑 `:api:neoforge:runData` 生成 `assets/numen_api/lang/{en_us,zh_cn}.json` 后重建并部署 api jar；在此之前游戏内文字可能显示 `numen.xxx` 原始键。已续期到 2026-11-13 并记录修法。
- 启动失败仍只落在 stdout；是否要写一个 `ENTER-BLOCKED.json` 标记（像 audit gate 那样可见），**待主人定**（会增加一个门禁产物，按“别加太多规则”的原则先不擅自加）。
