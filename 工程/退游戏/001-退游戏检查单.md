# 退游戏检查单（唯一真源）

> 关游戏 ≠ 结束。退游戏只认这一页；旧路径（`rdd架构\实机验证`、`rdd架构\杂项记录`）只作历史档案。

## 1 · 先写四行事实

1. **目标 / 判据**：批次卡里冻结的那份，不退不让。
2. **实际动作**：哪条链、哪个同伴、哪个工具、谁动的手。
3. **看到什么**：原始事件 / 时间码 / 坐标 / 前后差额。
4. **结论**：PASS / FAIL / UNKNOWN / NOT_COVERED，说不清就写 UNKNOWN。

## 2 · 记什么 → 进哪个文件夹

| 要记的东西 | 写到 | 一行格式 |
|---|---|---|
| 本轮实验数据（命令、退出码、哈希、曲线） | `知识库\实验数据记录\` | 在当月那份里加一节 |
| 验证卡（进过游戏就要） | `知识库\实验数据记录\` | `V-YYYYMMDD-NN` + 状态 ✅/❌/🟡 |
| 这批的目标与结果 | `知识库\批次卡\` | 00N-xxx批次卡.md |
| 坑与事故 | `知识库\踩过的坑记录\` | 时间 + 案例 + 原因 |
| 还欠的债 | `知识库\旧债记录\001-旧债清单.md` | 恢复判据 |
| 已发生的事 / commit | `知识库\项目开发修改总时间线\001-时间线.md` | 日期 + commit |
| 长期结论 / 契约变化 | `知识库\架构意图\` | 改现行那份，不新建 |
| 放不进以上的 | `知识库\杂项记录\` | 追加 |

**不写旧路径。** 旧 `实机验证\YYYY-MM.md` 只做只读档案，新记录一律进知识库。

## 3 · 算"记了"的标准

- 有命令、有退出码或原始事件、有时间、有对比基准。
- 只有"跑通了"、截图、模型自述 —— 不算。
- 路径只写知识库的；旧的看不懂的路径不许抄。

## 4 · 本次记录质量

关游戏后把四行事实补进原知识库主题，已有批次或月记录就更新原件；只更新本次改变的内容，不要求每轮同时写批次卡、时间线、坑、旧债和记忆图谱。值得复用的经验或实际新故障再按需沉淀。

运行 harness-gate.js postflight --record <原文件> --section "<本次小节标题>"，核对本次小节的结构、身份与原证坐标。不传记录只提醒，不会报告质量通过，也不锁下次进场。格式回写作规则（内部记录未公开）；结论本身仍要看原证。工具不能仅凭关键词保证事实正确。
