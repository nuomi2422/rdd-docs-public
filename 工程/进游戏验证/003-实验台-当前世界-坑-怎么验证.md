# 实验台：当前世界 / 坑 / 怎么验证

> 实验台围绕同一 run 组装环境、意图、时间线和历史对照，再按冻结判据裁决。部件与证据分工见[核心工具第 7 节](<001-进游戏核心工具.md#7--实验台内部怎样组装证据>)；历史快照不充当当前世界状态。
> 这一页只讲三件：世界里现在是什么、踩过哪些坑、怎么算验过。

## 1 · 运行身份

- 实例目录 `[内部路径已省略] Best of Twilight Forest`，存档名 `live`；脚本里的 `-Instance gpt` 是**参数名**，不是实例名。
- 换存档和停服分别核身份与保存回执，不用旧退出计数器作前置。

## 2 · 坑（都有原始案例，别凭记忆）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 新世界后同伴"动不了" | 曾出现绑定/身份未就绪，不能仅凭不动定因 | 先核本局身体、绑定、任务和原错；普通续跑不默认重建同伴或主链 |
| 传送 | 地下goto曾不可达 | 自然样本核可达性；获准的受控调试才传送并标介入 |
| 热替换 jar | `NoClassDefFoundError` 直接崩服 | 只走 mutation 部署，不热替换 |
| 绑床当睡着 | `bound=true` 但没睡 | 看本次睡眠/跨夜事件，绑定只算绑定 |
| 旧坐标跨世界 | 家/箱/复活点失效 | 按 `world` 身份隔离，旧坐标作废 |
| 人工介入 | 链 COMPLETED 但验收不合格 | 标 `intervention`，单独复验，不揉进自然 PASS |
| 只有近期日志 | 当成本次效果 | 只能算 telemetry |
| live 视图会覆盖 | 事后查不到 | 封存原始片段 + 事件 id + 时间 + hash |

## 3 · 怎么验证

1. **四问**：历史成就 / 当前状态 / 本次动作 / 持续经历 —— 先说是哪一种。
2. **判据档**：PASS / FAIL / UNKNOWN / NOT_COVERED；没覆盖就写没覆盖。
3. **三件套**：`bench health <runDir>` 判材料齐不齐 → `exp-judge` 按冻结判据裁决 → 每条结论挂原始锚点。
4. **稳定性说明覆盖**：按风险选时窗、场景或重复试验，报样本与局限；两次成功不自动证明稳定，不强制换seed或新建世界。
