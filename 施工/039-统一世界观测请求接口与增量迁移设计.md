## 1. 统一什么，不统一什么

统一请求/响应契约、身份、时效、覆盖、权限和订阅变化；逐步复用采集器和快照。不是一次合并所有模块，不是所有数据写入一个万能数据库。

Minecraft仍是真实世界；Settlement拥有设施登记，RDD拥有任务/完成历史，Numen拥有身体终态，Experience拥有经验。统一门面只按注册能力读取各所有者的事实/投影，不反向夺取写权限。任务判定可用更严格的可信服务端观测，同伴自动注入仍受其感知权限；同一协议不等于所有消费者看到相同信息。

## 2. 总体结构

~~~text
现有采集器/事实所有者
 → provider适配（服务端线程/预算/来源）
 → 不可变ObservationSnapshot + revision
 → WorldObservationService（拟议窄接口）
    ├ 自动环境摘要/主动聚焦
    ├ RDD条件评估/风险检查
    ├ 其它模块只读事实
    └ 实验台/轨迹引用
~~~

契约优先复用world-state-core现有ObservationRequest/ReadResult/覆盖与时效类型；公开访问面通过现有Numen API能力注册暴露，不让插件import另一个plugin实现或复制核心类进多个jar。先做依赖图/打包检查，再选最小DTO放置；禁止为了统一造第二套服务定位器。

## 3. 请求协议（示意，不是已存在的Java类）

~~~json
{
  "requestId":"q-uuid",
  "consumer":"rdd-condition",
  "subject":{"companionId":"uuid","worldId":"world","worldEpoch":"epoch","dimension":"minecraft:the_end"},
  "operation":"read",
  "topic":"combat.dragon",
  "selector":{"entityUuid":"dragon-uuid"},
  "fields":["health","phase","meleeReachable"],
  "freshness":{"maxAgeMs":500},
  "consistency":{"snapshotId":null,"maxSkewMs":100},
  "budget":{"maxItems":20,"maxBytes":12000,"deadlineMs":50},
  "cursor":null
}
~~~

consumer是审计标签，不是授权凭证。主体/权限由宿主认证上下文绑定，不信任模型传入admin或别的同伴UUID。selector只允许类型化、白名单选择，不执行任意脚本/表达式。

操作：catalog列可用主题/字段/代价/范围；read只读缓存；refresh显式受限采集，可返回PENDING；changes取指定游标之后变化。pin/聚焦只是客户端订阅策略，不能暗中触发无限全图扫描。

**任务评估通过batchRead取得一组有各自观测身份的前提。** 组合查询编号仅标记这次读取，不能把不同采样时刻改写成同一个snapshotId；逐条保留原snapshotId、observedTick和采样时间，核共同世界/采集会话及允许偏差。超出判据容差或身份缺失则不可核验；SAME_TICK也不等于锁住世界的原子事务。原因（2026-11-05）：两个旧值在同一次请求返回，不会变成“同时为真”；案例：一分钟前箱里有铁、一秒前身上有盾，不能凭新的组合编号宣布当前整备完成。

## 4. 响应协议与四类语义

响应含schemaVersion、requestId、snapshotId/revision、observedAt/tick/serverSession、source、visibilityPolicy、coverage、freshness、items、fieldStatus、continuation、warnings、cost、evidenceRefs。

- 传输/采集状态：OK/PARTIAL/PENDING/ERROR。OK不代表条件成立。
- 字段状态：KNOWN/UNKNOWN/STALE/UNSUPPORTED/DENIED；缺字段不填0/false。
- 业务条件：MATCHED/NOT_MATCHED/INVALID/NOT_VERIFIABLE，由消费者评估，不由门面擅自推进任务。
- 不存在证明：仅在scope、覆盖和新鲜度满足条件时canProveAbsence=true；局部0水晶不等于全场清零。

明确空数组、无权限、无provider、未加载、未来时间戳、实体已失效、预算未采等原因。运行id仅会话内有效，稳定身份用UUID+worldEpoch。派生近战机会带输入observationIds/规则版本，执行层动作前仍复核。

## 5. 增量有两种：逐步迁移与变化增量

### 逐步迁移：一主题一消费者

迁移表每项字段：topic、权威owner、provider、已接消费者、旧读取点、权限/TTL、生产状态、回归卡、回退开关、旁路原因及退出条件。

状态：LEGACY_ONLY→ADAPTER_READY→SHADOW_COMPARE→CONSUMER_SWITCHED→LEGACY_RETIRED。

1. 首批适配现有自身/附近实体数据，不改变语义，证明接口实际有调用。
2. 自动env先切一个主题，共享其快照供主动展开；旧文本路径停止重复注入。
3. RDD选择一个条件切换，先shadow比较同身份/时刻/覆盖的旧新结果；差异有原因，不能以旧代码永远正确作oracle。
4. 任务链/其它插件逐个迁，必要API兼容测试与实机正反例通过后退旧读点。
5. 短期未支持的能力保留**登记的legacy适配器**，暴露source/限制，不静默fallback。禁止为满足新文档一次拔掉所有直接读世界代码。

### changes：可靠变化游标

cursor绑定worldEpoch、subject、topic、权限视图和schema；换世界/范围/权限或游标过期返回RESET_REQUIRED。返回UPSERT/REMOVE/INVALIDATE及fromRevision/toRevision；REMOVE必须有真实来源，过期/不可见只能INVALIDATE，不伪装实体消失。

保留期之外或中间丢事件明确GAP，客户端先全量snapshot再追changes。重复可幂等，同源revision单调；跨源不凭墙钟编造全序。序列、缓存与历史索引可重建，业务真源不随订阅删除。

## 6. 任务链如何消费（重点）

条件评估输入绑定chainInstanceId/planRevision/subtaskId和snapshotId，返回结果+观测引用+原因。提交状态前重核链代次；迟到事实不能推进新任务。对当前持有/穿戴/指定箱库存的判据必须选择对应topic，历史成就不能替代本轮动作。

NOT_VERIFIABLE等待可恢复采集/刷新并限频诊断，不增加动作失败；INVALID走条件修复；NOT_MATCHED正常等待/策略；MATCHED才提供完成证据。不要直接把响应OK映射为MATCHED。涉及多个前提必须检查快照一致性与证据范围。

采集失败不在请求组装线程同步扫世界兜底；任务tick不等待外网/截图；安全反射保持本地执行，不等待统一服务返回才救命。服务不可用时危险派工失败关闭但保留安全观测/撤离路径，不全局卡死。

## 7. 末影龙复用示例

combat.dragon提供血量/阶段；combat.crystals提供范围计数与覆盖；combat.affordance提供当下近战前提及原因。自动摘要、AI主动展开、任务条件读取同一观测来源但各有授权范围和预算。

同伴可见视图：只知本范围2个水晶，全场UNKNOWN；授权任务评估若用服务器全场事实必须明确来源，不能将该事实偷偷注入自然视野。龙落台与meleeReachable分别判断。条件“清理全部水晶”在局部覆盖时不能完成。专题详细例子见[038](<038-主动环境聚焦与同伴轨迹架构方案.md>)。

### 11.2 现有 world-state-core 类型（可直接复用的）

| 类型 | 现状 | 对 039 的差距 |
|---|---|---|
| `Topic` | ENVIRONMENT / BLOCKS / ENTITIES / CONTAINERS / FACILITIES | 039 的 `combat.dragon / combat.crystals` 等专题尚未有 topic（需要新增还是映射到 ENTITIES？**待定**） |
| `ObservationRequest` | `(topic, dimension, target, filter, bounds)` 5 个字段 | 缺 039 的 consumer/subject(worldEpoch)/fields/freshness/consistency/budget/cursor |

| `WorldIdentity` | 已有 worldEpoch 概念 | 与 039 的 subject.worldEpoch 对得上 |

### 11.3 打包与依赖（039 §2 要求先查）

- `world-state-core` **只被 `plugins/worldstate` 内嵌**（`from(sourceSets.main.output)`），今天**没有**"同一份核心类复制进多个 jar"。
- `plugins/rdd` 不依赖 `world-state-core`，也没有 import 其它插件实现 → 039 说的"不让插件 import 另一个 plugin 实现"目前成立。
- **但**：rdd 若要调用，缺一条公开通道。查 `NumenApi`/`NumenPlugins` 现状——只有 `registerTool / on / contributeState / enqueue / configDir` 这类扩展点，**没有"按类型登记/查找能力"的接口**。039 §2 写的"通过现有 Numen API 能力注册暴露"目前**不成立**：这个接缝还不存在。

### 11.4 由此得出的最小决策（待做，不是已做）

1. **DTO 放哪**：`ObservationRequest/ReadResult/Coverage/FailReason` 若要跨插件用，必须落在 `api:common`（所有插件都可见）；`world-state-core` 保留采集实现。**不建议**为此把 world-state-core 塞进每个插件 jar。
2. **接缝**：要么给 `NumenApi` 加一个最小的 `capability(Class<T>, T)` 登记/查找（一次改动、全插件受益），要么在 `api:common` 放一个极小的静态持有者。前者的风险是"又一个服务定位器"（039 明令禁止第二套），所以**倾向**在 `NumenApi` 里加，并把查找语义限定为"按接口登记，按接口取，找不到就 null"。
3. **U1 的消费者**：优先 `ENVIRONMENT`（已有 provider、已有真实调用方 RddEnvBlock），把它从"扫描 + 静态攻略"切成"读快照 + 覆盖/时效标注"，同时把末地攻略挪出 env（它不该是环境事实）。

> 本节只是对照结论；上述三项都**未实施**。

## 27. D-017 结案：重启后修订号归零 → 所有刷新被静默丢弃（2026-11-05 03:35–04:00）

| 步 | 实际 |
|---|---|
| 症状 | 能力侧每 5 秒报 `cap_refresh SUCCESS`（新增诊断事件，见 `[内部日志未公开]`），但 `observations.json` 里的观测一直是 `HISTORICAL`、age 几百秒，env 只能靠过期数据 + 标记撑着 |

## 37. 当前核心契约冻结（2026-11-05晚，043 B1；实现状态另查交付回执）

### 37.1 不再新造世界源

继续使用现有 WorldStateService、QueryService、ObservationStore、采集器注册和 WorldObservationService；API（模块间公开接口）只扩窄契约，不另建总线或数据库。此冻结时点四主题为environment、entities、blocks、containers；2026-11-06主树已追加SELF与readSelf缓存入口，当前五采集器范围见008，部署/实机见043。facilities/专题/地图/完整轨迹不可因接口存在就当已完成。原因：源码已经有4条真实采集链；案例：新开“统一服务”再绕开它们会使同一箱子拥有两份新鲜度政策。

### 37.2 观测身份与时间

- 世界身份由实际存档目录规范化绝对路径加摘要构成，不以显示名或单独目录名跨实例合并。路径不可取时使用隔离的unknown标识；不得参与严格一致性通过。旧缓存不搬写成新世界，新查询可PENDING等待显式刷新。存档迁移/复制后身份变化需要显式重同步，不猜同一世界。原因：两个实例都可叫live；案例：实验副本与自然运行不得互相提供装备证据。
- serverSession为一次真实服务器对象生命周期的随机身份；同进程退回菜单再进世界也换。观测在采样时记下session，不在读取旧值时改贴当前session。磁盘载入一律历史；同session也不能自动洗新。worldEpoch（业务世界代次）、serverSession（本次打开）与变化流epoch（日志代次）不是同一个字段，当前核心只实现serverSession；持久业务世界代次后续补，不伪称已齐。原因：tick会复用；案例：重开世界后的第100tick不能匹配上一轮第100tick。
- 公开响应 metadata：worldId、serverSession、dimension、subjectId（仅明确主体时有）、source、observationKey、revision、observedAtMs、freshness、visibility、validUntilMs（由宿主实际主题有效期与调用方maxAge取更严者计算，未知为0）。缺主体不填“当前同伴”，如环境是维度事实；工具外层另绑调用同伴。unknownFields/staleFields保留。未来/非正时间戳不可CURRENT；空容器也有独立freshness，不能因没有items就丢过期状态。原因：字段空表没有可标stale的元素；案例：旧空箱不能给“不存在铁”提供当前证据。
- snapshotId表示单条原始观测的身份（会话＋键摘要＋修订），不是多个provider的原子编号；watermark继续是变化日志的读取水位，按041处理，不拿它当页号或世界时间。

### 37.3 有界组合缓存读取

在现有能力上增加 `batchRead(ObservationBatch.Query)` 与 `catalog()`；旧read/refresh/changes签名保留，Response旧8参构造仍可用但metadata=UNKNOWN，不能满足新组合校验。

组合请求含requestId、expectedWorldId、expectedServerSession、requests、maxSkewMs、deadlineMs。最多16项；每项回传原topic及metadata；总结果含status、consistency、observedSkewMs、responses和reason。缺项/超时不伪装完整；按请求顺序返回已读取前缀并明确原因。

一致性：SAME_TICK＝共同世界/会话、均当前完整且游戏tick相同并满足墙钟偏差；BOUNDED_SKEW＝tick不一但采样偏差符合消费者要求；NOT_COHERENT＝世界/会话错配或超偏差；UNKNOWN＝缺身份、未采集、历史/过期/覆盖不足/字段未知。coherent只表示观测组合可用，业务条件仍独立判断，动作前仍复核。四个已接主题校验必需字段；空environment不能通过，完整当前且身份明确的空containers可以表示已知为空。返回前统一用最后时刻再次检查每条validUntilMs与maxAge，恰在截止点可用、超过即不可用。mapper使用原请求生成的完整ObservationKey核对结果；组合层再核player选择器与subjectId、拒负tick，不另复制一套键编码协议。

默认组合截止50毫秒，上限1000毫秒；单项默认64条、上限256条；组合maxSkewMs默认由工具设100毫秒，业务消费者须按条件选择，不能无限放大以“通过”。条目截断降PARTIAL并解释遗漏；maxAgeMs对主题有效期再收紧，不把0/负值解释成永不过期。截止时间是读取前后合作式检查，不会强行中断MC线程；大扫描仍有原体积预算，增量采样另批实施。原因：验收预算必须说明单位；案例：一次慢读虽完成，超截止也不能当及时快照使用。

**本批限制：** 没有跨provider事务锁、历史版本回读、全局字段级权限系统，也没有硬字节预算；maxItems限制条目，不保证每条payload很小。后续注册高体积主题之前，必须补每主题字段/字节限额，不能把当前条数上限宣传成完整资源治理。

### 37.4 现有工具新增操作，不复制业务实现

`world_state action=catalog`只列当前已接主题；`action=batch_read`以queries传旧四主题参数（复用WorldStateArgs/公布schema），可传max_age_ms、max_items、max_skew_ms、deadline_ms。当前工具组合读由宿主self绑定世界/会话/同伴，只准当前维度、各轴±32格的立方近场盒子/箱子或自身背包（不是欧氏半径32格）；它是SERVER_LOADED增强近场，不宣称视线可见。consumer或模型传入的UUID不能提权。不隐式刷新、不移动、不加载远方区块。

~~~json
{"action":"batch_read","queries":[{"topic":"environment"},{"topic":"containers","container":"player:<真实同伴UUID>"}],"max_age_ms":2000,"max_skew_ms":100,"max_items":64,"deadline_ms":50}
~~~

示例的UUID是占位符，实际必须来自当前同伴。先前refresh若没采同样键，本次PENDING/不可核验是正确结果。工具返回传输成功不等于业务成立，读取result.status/consistency及每条元数据。外部AI仍走既有授权工具/实验台适配，未新增全网HTTP端口。

**兼容边界必须明示：** 旧read/refresh/changes保留，尚未全面接上述近场权限和组合元数据输出；可信插件API仍由宿主代码约束。新batch_read不是整个旧工具已完成权限加固的证明。B2迁移时先对旧消费者和管理员诊断用途定权限，再逐入口迁移；不能仅靠关闭新入口当作旧接口权限已经安全。

### 37.5 后续扩展统一归属

self/nearby/实体详情由服务端线程采样入同一观测核心；task/asset/facility通过原所有者的公开能力只读投影；注意力配置只选字段不写事实；路线图只持新增行走证据并引用旧地点；轨迹索引只引用monitor原件与已送达请求。每个消费者登记LEGACY→ADAPTER→SHADOW→SWITCH→RETIRED及回退条件，动作安全反射可保留本地最新状态，但不得把其旁路结果悄悄混成已验证统一观测。
