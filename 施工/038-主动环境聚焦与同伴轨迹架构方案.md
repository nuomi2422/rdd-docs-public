## 1. 先回答：要造的不是更长提示词，是“能选择看哪里”的观察系统

AI的有效能力受四件事共同限制：**能观察什么、能调用什么动作、两者的延迟/可靠性、如何决策**。更完整感知能解锁能力，但不能代替缺失的执行工具，也不能保证模型一定采用。

人类式借鉴是“周边持续监测＋当前焦点精看＋记得没在看的地方”，不是一次看到全世界。

设计两个共用身份与证据的产品：

1. **环境工作台**：可浏览/展开的世界、实体、设施、资源、风险和动作前提；按任务自动选焦点，AI可改焦点或补查。
2. **同伴轨迹**：每同伴独立，按时间前后展开“当时收到什么→目标/计划→工具受理→真实终态→世界变化→对话/可见决策摘要→截图”。用户、外部AI、学习线和游戏内AI共用可查询证据，不共享全部权限；外部会话须有真实授权来源才能关联，不能把命令使用记录冒充完整外部AI行动史。

### 1.1 核心动机与常驻目标（2026-11-05产品决定）

- **生存、省时、稳重是服务主人任务链的动机，不是无限保守。** 目标是少做无效动作、保住继续推进任务的能力，在有证据且可接受的风险下行动；不把“永远安全”变成不出门、不探索、不战斗。原因：生存本身不是替代主任务的新主线；案例（设计示例，非实测）：低血先避险补给，恢复后继续取材，而非不断建避难所。这里只定义产品意图，不改模型人格或运行提示。
- **常驻展示三层目标：主人总目标→当前阶段/子目标→眼前执行步。** 同时展示当前身体任务与阻塞，缺层明确未提供，不由观察层自行补计划或推进完成。原因：只显示眼前动作会丢失“为什么做”；案例（设计示例）：通关→准备下界补给→取回已知箱中的食物，三层可展开但不各自争用身体。
- **阻塞时只产生轻任务候选，不抢身体。** 可提示检索攻略、核对材料、等待新观测或提出短支线；是否执行仍由现有任务/身体所有者裁决，恢复后回主线。原因：观察层不是第二个调度器；案例（设计示例）：熔炉等待时可建议检查库存，但已有危险撤离动作不能被“顺手收集”打断。

**关键误导：** RddEnvBlock末地分支写死“10根柱、水晶不清完龙不掉血、落中央才能砍”。这是攻略而非实时观测；水晶治疗不等于龙绝对免伤，落台也不等于当前身体能近战。低血分支也直接写“持续掉血”，单次hp低不能证明持续下降。改为观测值、派生趋势、策略建议分栏，不让经验伪装事实。

另一风险：环境块当前直接读取方块/背包，不能把新增大扫描塞进请求组装线程。服务端采样→不可变缓存→请求读取是新实现边界；不要在任意contributeState回调扫世界。

### 2.1 最小施工接点（历史坐标作导航，落码前重核）

- 服务端采样复用RddDetector onServerTick（内部记录未公开），在runtime判空之前也更新必要自身感知；缓存不要求同伴必须已有主线。读取/刷新服务与采集器解耦，不把全部感知职责永久绑在RDD插件。
- 自动通路沿RddPlugin.withAssets（内部记录未公开）→EntityAgentLoop（内部记录未公开）预算→AgentRequestContext.attach（内部记录未公开）→实际LLM请求；主请求/重试都核送达。插件块当前required=true，新增焦点必须有自身硬预算，不能全标required挤掉其他模块。
- RddEnvBlock现有400字符压缩不保证末尾关键字段保留；先做结构化优先选择再渲染，不能在最终字符串上按原顺序硬截。
- 主动同伴入口优先扩展现有perception（look_around/scan等）为统一薄门面；world_probe保持管理员诊断定位，不直接把players/规则/跨坐标全知信息自动灌入同伴。接口形状借目录与read/refresh，不代表两个权限域合并。
- 动作时间线复用action-ledger（内部记录未公开）的受理/异步终态/重复回执/UNKNOWN处理，不另写一套“success即完成”。原始tool_call只有参数长度时，从同request的可见llm_response.tool_calls关联参数，不能假称调用流本身已存全参数。
- LlmObservation（内部记录未公开）已排除hidden reasoning；对话流摘要也可能截短，展开应回可见响应原件。当前相机接口及实验台服务（内部记录未公开）已有媒体查看能力，沿原manifest扩展，非另建录像系统。

## 3. 环境架构：一个事实底座，两种取用，三个视图

~~~text
Minecraft服务端/已有设施与任务状态
  → 有预算的采集器（原线程规则、加载与权限约束）
  → 不可变观测快照（来源/身份/时间/覆盖/新鲜度）
  → 任务焦点选择与派生关系（不写世界真值）
      ├ 自动摘要：每次请求的关键事实/变化/缺口
      └ 主动查询：发现目录→展开→刷新→短期钉住→释放
  → 最终请求组装 + 实际交付回执
  → 实验台：现实视图 / 当时AI视图 / 事后对照视图
~~~

**同一观测来源，保留各自写权（2026-11-05产品决定）：** 自动注入、游戏内主动查询、外部AI与用户工作台沿统一观测能力取证；任务判定逐主题迁入同源读取，不一次替换所有旧逻辑。任务推进仍归RDD，身体执行仍归Numen/执行层，设施资产仍归原所有者；观察层只读投影，不写它们的完成状态。原因：同源不等于同权限或同所有者；案例：外部诊断取得服务器覆盖，不应自动变成同伴自然可见，也不能因“观测成功”替任务链宣布完成。协议与迁移细则见[039](<039-统一世界观测请求接口与增量迁移设计.md>)。

三个视图必须可切换：
- **现实视图**：当前/指定时间采到的世界事实，按来源与权限显示。
- **AI视图**：该次最终请求真正送达的内容，不是“缓存里曾经存在”。
- **对照视图**：标出可采但没采、采到没选、选中被预算裁掉、发送失败、已送达但动作未利用。不能单凭送达推断模型确实注意到。

### 3.1 感知目录（先有通用维度，再挂专题）

| 维度 | 需要知道什么 | 示例按需展开 |
|---|---|---|
| 自身 | 血/饥饿/装备/效果/位置与运动 | 最近受伤趋势、武器耐久 |
| 任务 | 当前目标、子步、成功谓词、阻塞、执行身份 | 整链/依赖/历史修订 |
| 空间 | 地形、落差、可通行路径与已知盲区 | 某方向/楼层/区域、局部小地图 |
| 实体 | 身份、位置、可见性、状态、敌我/互动 | 某只龙/村民/掉落详情 |
| 资源设施 | 已观测容器/工作站/基地与来源 | 指定箱、生产条件、备用 |
| 风险机会 | 攻击窗口、虚空、火/气息、撤离路径 | 本动作阻塞原因/可验证前提 |
| 动态变化 | 自上次请求的增减/出现/消失/阶段切换 | 时间窗口内变化轨迹 |
| 不确定性 | 过期/未加载/看不见/无provider/预算未采 | 如何得到缺失信息 |

折叠层级建议：世界→维度→已知区域/基地→实体/设施→状态/关系。关系例如“龙正在被该水晶治疗”“目标在头部近战范围外”，都要带生成依据和版本，不用LLM猜出实时事实。

**常驻卡最小内容（2026-11-05产品决定，字段是否已采集逐项核实）：**

- **自身卡：** 血量、饱食、装备及耐久、状态效果、位置/维度、身体正在做什么；展示9个快捷栏位，加副手作为第10个显示位，保留原槽位身份，**不是把游戏快捷栏改成10格**。情绪仅在有明确可用来源时展示来源和时间，否则为`UNKNOWN`（未知），不从一句对话猜实时情绪。原因：可见面应反映真实身体而非虚构状态；案例（设计示例）：盾牌在副手可显示为第10位，不代表增加一个可切换快捷栏槽。
- **周边卡：** 世界时间、天气、局部空间/通行与安全风险、附近实体、贵重或任务相关掉落、地形与落差。附近实体默认显示5个，可配置到8个作为初始产品限额；按风险/任务相关性选择，并告知遗漏数量和扫描覆盖，紧急危险不能因排序靠后被无声裁掉。原因：避免信息洪水又不假装全场覆盖；案例（设计示例）：8个非威胁实体在附近时，新增逼近怪物仍应进入风险摘要，而不是被“前5个”藏掉。
- **目标卡：** 使用§1.1三层目标、当前阻塞与轻任务候选；卡片能展开事实原件与新鲜度，不把最后一次缓存写成“此刻一定如此”。原因：缓存、候选与已执行是三件事；案例（设计示例）：看到旧箱内食物记录，只能建议复查，不能宣布当前补给已到手。

### 3.2 观察层：常驻底线＋限额热挂载＋主动展开

**以下是2026-11-05产品规则，不表示运行提示或配置已经修改。**

- **常驻不可关闭：** 自身、三层目标/身体执行、周边关键风险、严重变化与观测缺口始终保留最小摘要，不受专题卸载影响。原因：注意力切换不能抹掉生存和主任务底线；案例（设计示例）：展开箱子库存时仍应看到正在掉血的已观测趋势，而非让库存占满提示。缺测写未知，常驻不等于强制无限扫描。
- **专题可限额热挂载：** 按目标类型、维度、实体和真实变化选择自动专题，AI也可显式短期钉住关注点。建议先试“最多2个自动专题＋4个显式焦点”，都有存活时限（TTL）、总字节/条目/采样预算、触发去抖与撤销条件；换世界、换主体、目标失效时清理。挂载不提升权限、不新增动作许可。原因：专题应随任务收放而非无限常驻；案例（设计示例）：离开末地后撤销旧龙焦点，不能沿用上一世界的龙血量。
- **主动地图/轨迹展开：** 地点、设施、路线证据、实体详情、旧行动片段和原始请求按需分页取用；原始长JSON、图片和录像以引用打开，不全塞进常驻提示。原因：长记忆需要能检索而非每轮重放；案例（设计示例）：任务要去旧矿洞时展开该地点与实走证据，而不是加载整天日志。

优先级仍为紧急生存变化→当前动作前提/失效→当前目标缺口→显式焦点→其他相关线索。预算溢出返回遗漏目录与原因，不静默裁掉唯一关键字段。约1500个模型词元（tokens）只保留为2026-11-04提出的总环境预算待测起点；2＋4的限额也须随真实送达与行为验证，不宣称已证最佳。

> **首批实现状态（2026-11-07）**：显式短期焦点已有 `world_state action=pin|unpin`（topic 限 environment/entities，TTL 默认 120s、每同伴最多 4、**复用不续期**），状态挂 `WorldStateService` 生命周期、按 world/session/companion 隔离；规划侧与执行侧（同一 projector，经既有 contributeExecutorKnowledge 贡献口）只读缓存投影（缺失/错身份/过期 → UNKNOWN）。**已实机验**：catalog/pin 复用同 pin_id 同 expires/unpin 幂等/正常保存退出；**未覆盖**：规划投影未自然出现（NOT_COVERED）、执行侧投影未接、目标失效自动撤销未实现。

**服务端更新频率≠模型请求频率。** 战斗局部状态可先试5Hz采样，计划摘要在请求时取最新；阶段切换/目标丢失发变化通知并去抖。移动/攻击/躲避等短周期判断留在已有执行层，不能等LLM几秒一轮来接近战窗口。模型选策略，执行层使用新鲜观测再判动作前提。

### 3.3 主动取用体验（协议唯一正文在039）

2026-11-05收口：沿现有观测目录/工具扩展薄门面，不新增一组同义工具。使用路径是“找得到主题→读已有事实→展开详情→有需要才请求刷新→短期关注→释放”；具体操作、响应和错误字段只由[039](<039-统一世界观测请求接口与增量迁移设计.md>)维护。原因：产品示例不应变成第二份协议；案例：展开旧地点可能只是读历史，不应因一个“展开”按钮暗中扫描远方。

“想看哪里就看哪里”是**可表达关注点并知道能否取得**，不是强制加载全地图、透视所有箱子。读取不隐式采集；刷新受线程、预算、权限约束。未知区域可给位置/视角调整建议，但移动是独立动作，不偷偷传送；管理员诊断入口与同伴感知不合并权限。

### 3.4 专题学习包：选择字段与攻略，不替世界下结论

## 6. 每同伴轨迹：按因果关联，按时间浏览

### 6.1 不新造业务真源

- 轨迹：跨同伴串线=0、重复事件可幂等、半行/轮转不静默丢、受理→终态匹配覆盖、媒体关联质量、导出无未来泄漏。
- 低频和稀有失败要定向测试；一次示范不叫稳定有效。模型强弱与感知改进分别对照，不将全部效果归模型价格。
