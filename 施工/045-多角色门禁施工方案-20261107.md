大白话：现在门禁是「所有人同一张考卷」。指挥官不施工却要被 jar 编译类判据挡；学习 AI 不进游戏却要过「游戏已关」「验证卡回填」。结果是他们要么违规，要么整体 `gateMode=off` 绕过去 —— **绕过去了等于没门禁**，这才是真问题。

## 2. 怎么分（做法，不是新造一套门禁）

三处小改，全部复用现有机制：

1. **registry.json** 新增顶层 `roles` 段，声明角色清单与中文名；每条判据加一个可选字段 `appliesTo: ["worker"]`（缺省 = 全角色，不写就是所有人都跑）。
2. **harness-gate.js** 加 `--role <id>`（也可读环境变量 `RDD_GATE_ROLE`）；在 `applyGateMode()` **同一位置**再套一层角色过滤，不属于当前角色的项 → SKIP，理由写「本角色不适用」。**不改判据本身、不改 groups、不改强度。**
3. **gate-switches.json** 加一段 `roles` 覆盖开关（可选），便于临时用全量考卷跑某个角色。

不做的事（先划死，防止越搞越复杂 —— 主人原话「怕越加越冗杂，后面维护崩」）：
- 不做第二份角色门禁文件（多真源必炸）。
- 不做「每个角色一套独立判据代码」（43 项会变 129 项，维护崩）。
- 不在门禁里做「谁有权限 approval」—— 那是 DSH 的 preset 层（见 §5）。

## 3. 四条硬约束（每一条都对应过去的坑）

1. **跳过 ≠ 通过。** SKIP 行必须打印并写明「本角色不适用，不算通过」，同时不进总判。理由：主人点名的 AI 盲点就是「静默通过」；`$askNote` 里 P10/P10c 的教训同源 —— 一条永远无法自动满足的项会把门禁永久钉死。
2. **每个角色至少保留 1 条 BLOCK，否则 selftest 直接 FAIL。** 防止某个角色被配成空壳门禁（永远绿 = 比没有更坏）。
3. **缺省不带 `--role` = 全量跑**，与今天逐字节一致。所有老脚本、老习惯不受影响。
4. **提醒桶（REMIND，9 项）不参与角色过滤，永远全打。** 它们本来就不影响总判，只鼓励看一眼；去掉纯亏。

## 5. 另一半：DSH 侧（工具面，不是门禁面）

RDD 门禁只管「这一轮该不该放行」，**管不了这个 AI 能调什么工具**。工具面在 DSH 的 preset：

- 现状：desktop profile 只有 `preset-standard` 和 `preset-ptc` 两个，工具清单**完全一样**；`permission.presets` 里 `defaultPreset: danger-full-access`，**对所有角色都不设审批**。
- 要做角色分档，得在 `[本机路径已省略]` 里加 `preset-commander` / `preset-worker` / `preset-learner` 三个 entry，并给 `permission.presets` 分档（如 commander = workspace-write + ask，worker = danger-full-access，learner = read-only）。
- ⚠️ 两个已知坑：① 官方语义是**整体替换不合并**（`cordis.patch.yml` 里已有同名注释），必须写完整 plugins 列表；② DSH 升级后要重新同步（同 `dsh-smart-compact` 的坑，见 `踩过的坑记录\009`）。
- **写错 = 会话起不来**，所以放三期，且先复制标准 preset 再删减，不手搓。

## 14. 记账只在 CLI 生效（2026-11-08 08:02 实测，待重启解除）

给架构 MCP 加 `logCall` 之后，实测发现：**只有 `node cli.mjs <tool>` 会写 `[内部日志未公开]`，会话内经由运行中 MCP server 的 `arch_*` 调用不写**——因为那个 server 进程是在改代码之前启动的，跑的还是旧代码。

后果：C1（2 轮内读过架构导航）会把「我真的调了 arch_status」判成 BLOCK。这是门禁诚实、仪表没通电，不是判据错。

处理：
- 短期：每轮用 `node cli.mjs arch_status --focus harness` 兜底留痕（已验证 C1 立刻转绿）；
- 根治：重启 DSH，让 MCP server 加载带 `logCall` 的新代码，之后会话内调用也会记账。
- 这也解释了 C1 为什么突然红：它不是误报，是在提醒「你最近 40 分钟没有可追溯的架构调用」。

## 8. 一句话总结

门禁引擎不用重写，加一个「这条判据归谁」的字段和一个 `--role` 参数就能分角色；危险的不是改代码，是**跳过被当成通过**，所以四条硬约束必须一起落地。
