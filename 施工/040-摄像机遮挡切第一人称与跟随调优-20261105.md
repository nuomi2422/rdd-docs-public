# 摄像机：遮挡切第一人称 + 跟随刷新率施工单（2026-11-05）

## 0. 用户反馈（原话要点）

1. 视频刷新率不高，帧率很低，镜头会抖动。
2. 有一个换视角的机制；建议：**被挡住就切第一人称，停留约 10 秒，再缓慢变回第三人称**。
3. **自动检测**：开关打开后，每秒检测与绑定目标是否距离过远，远就**静默传送**（不进聊天栏）。

## 1. 现状盘点（代码实测，非推测）

| 能力 | 现状 | 位置 |
|---|---|---|
| 静默传送跟随 | **已实现**：每 tick 检查距离，>64 格触发，`ServerPlayer.connection.teleport` 服务端静默执行，无聊天输出；40 tick 丢失判定 + 100 tick 冷却 + 40 tick 最小间隔 | `tether/CompanionTether.java` |
| 遮挡处理 | **只有"拉近"**：8 角点探针（SHOULDER/CINEMATIC）+ 视线裁剪（ORBIT/LOCK），被挡就把镜头收到障碍前，**没有状态机、没有滞回** | `mixin/MixinCamera.java` `numencam$maxZoom` / `numencam$keepLineOfSight` |
| 录像帧率 | **默认 10 fps**（`DEFAULT_FPS = 10`）；tick 驱动，靠 tick 间隔取帧 | `rec/VideoRecorder.java` |
| 跨帧平滑 | 有 `CameraRig.damp()`；`CINEMATIC` 模式另有阻尼 | `cam/CameraRig.java` |

**结论：第 3 条（静默跟随）其实已经存在，只是默认没开、阈值 64 格偏大。**
第 1、2 条才是真缺口。

## 2. 为什么会抖、为什么帧率低

1. **采集帧率低**：10 fps 抓帧 → 任何连续运动都像"一格一格"。
2. **拉近/拉回没有滞回**：墙一挡住镜头就瞬间收到目标背上，墙一让开又瞬间弹回原位 —— 这是最刺眼的"抖动"，不是相机在晃，是**距离在跳**。
3. 录像时 PNG 压缩在 IO 线程，但主线程仍在每秒 10 次 GL 读回，低配机器会掉帧。

## 3. 方案

### 3.1 遮挡 → 第一人称（核心）

新增状态机（放在 `CameraRig`，MixinCamera 只取结果）：

```
每 tick：
  blocked = 从目标眼睛向"理想第三视角机位"打 ClipContext，命中点 < 理想距离 - 0.5
  if blocked:
      blend → 1（0.25s 内到位），并刷新 holdUntil = now + 10s
  else if now > holdUntil:
      blend → 0（2s 内缓变回第三视角）
```

- `blend = 1` 时相机在目标眼睛处（第一人称），朝向 = 目标视线。
- `blend` 在 0..1 之间时位置线性插值（第一人称↔第三人称），视觉上是"缓缓拉开"。
- **最短停留 10 秒**：避免墙缝里来回闪。
- 与 `CINEMATIC` 的阻尼叠加时，先算 blend 再 damp，避免二次平滑把切换拖成慢动作。

### 3.2 帧率

- `VideoRecorder.DEFAULT_FPS`：10 → **20**（tick 驱动下的自然上限，1 tick 1 帧）。
- `/cam rec start fps:<n>` 仍可覆盖；>20 只能靠同 tick 多次抓帧，**默认不启用**（会把渲染线程读回翻倍，低配机器更卡）。
- `numencam-mcp` 的 `cam_rec` 默认值同步改成 20，README 同步。

### 3.3 抖动

- 上面 3.1 的滞回本身就是主要修法。
- 另外把"拉近"改成**按秒缓变**：`maxZoom` 结果与上一帧结果做 8 tick 线性过渡，避免瞬间弹跳。

### 3.4 跟随（已有，调参即可）

- `follow` 默认开启（绑定时自动开）。
- 阈值默认 64 → **32 格**（拍人像时 64 格已经很远，画面里人只剩几个像素）。
- 检查频率保持每 tick（比"每秒"更细，不额外开销）。
- 静默传送已是服务端 `connection.teleport`，**不进聊天栏**，符合用户要求。

## 4. 验收

1. 站在墙角/树后：镜头 0.25 秒内切到第一人称，**停留 ≥10 秒**，离开遮挡后 2 秒内缓变回第三人称，全程无瞬间弹跳。
2. 录像 10 秒：ffprobe 报 20 fps；肉眼无"定格感"。
3. 牵引：把同伴 tp 走 40 格 → 1 秒内玩家被静默带过去，聊天栏无输出。
4. 失败回退：任一步异常，`/cam off` 能立刻交还原版相机。

## 5. 风险

- 第一人称时若目标贴墙，眼睛可能嵌进方块 → 用 `ClipContext` 从眼睛再回推 0.3 格做保护。
- 联机服拿不到 integrated server，静默传送退化为 /tp（会刷屏）——这一点代码里已有注释，保留。
