## 5. 最小方案（无隐式通道）

1. **新增显式返回**：`NumenGateway.enqueueCommand(UUID,String)` 返回 `CommandReceipt{Delivery delivery, String commandId, WorldContextStamp.Token identity}`；`enqueue()` 保持原样（内部可复用）。
2. **新增 MCP 工具** `enqueue_receipt`（不改旧 `enqueue`）：`handleEnqueueReceipt` 调 `NumenActuator.enqueueReceipt(...)`，返回 JSON `{delivery,commandId,identity{world_id,server_session,epoch},companion_uuid}`；拿不到 identity 就写 null。
3. **runner**：`/stop` 改用 `enqueue_receipt`；只有 `commandId` 非空才作为 `expectedCommandId`，并把 `identity` 作为 scope。
4. **scope 透传**：`waitForStopEffective({scope})` 透传给 `scanOwnerStop`；`owner_stop` 的 `command_correlation_id===commandId` 且顶层 `world_id/server_session/epoch` 与 receipt 一致才 EFFECTIVE；epoch 不一致 → UNKNOWN。
5. **不做的**：线程局部隐式回传、按时间/顺序反查、把信封 stamp 直接当权威、把旧 `enqueue` 文本改成 JSON。
