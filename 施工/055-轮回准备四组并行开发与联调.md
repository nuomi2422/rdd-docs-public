# 055 · 轮回准备：四组并行开发与联调

**给指挥官：** 按下面四包派，每人对一个实际使用方和一组正反例负责，四人中指定一人兼主工。**055 既交四包，也负责跨包联调；053 保留轮回总目标和正式通关。** 安家过夜只验第一次接通，不限制各包独立开发，更不能代签全部准备完成。

## 0. 指挥官先读：本轮是完整轮回准备，不是四项小补丁

**2026-11-21 主人抽查后明确确认，要求写回防止误解。** 本轮继续进入轮回准备阶段，四包都要修、都要接到真实使用处；以 053 和现行架构的完整能力为范围。本单中的“先接哪一段”、安家过夜、箱/炉、采矿等都是施工起点和验收样例，**不能解释成只做这些例子就交账**。分批交付不等于把其余能力移出本工程。这里的四包属于同一第四工程组的工作分解，不是再新建四支管理团队。

### 0.1 共同数据底座必须完整接通

按[统一世界数据契约](<../架构/008-WorldState模块.md#L15-L32>)和[053 数据接线](<053-轮回训练施工单.md#L164-L170>)完成：

**既有采集器/领域事件 → 同身份增量获取 → 原始观测存储 → 公共有界计算 → 派生存储/缓存及失效更新 → 统一读取与检索 → AC、任务、环境专题、规划/执行、学习的实际读端。**

- **统一获取与存储：** 复用生产源、原观测库及领域投影，维护时间、覆盖、身份、输入修订和更新/失效；不让每个 AC 各扫各存，也不把短期观测、长期语义资产和历史实验轨迹混为当前真值。统一契约不要求所有领域迁入一个数据库，原写权保留。
- **统一计算：** 算术、比较、范围过滤、聚合、排序等形成可复用能力，输入输出类型、单位、缺值、算法版本及成本明确。计算结果依赖当前输入；输入、范围或算法变了应失效/重算，不能用旧风险分数冒新现场。三包主责公共数据及派生契约，二包负责把这些能力绑定成 AC 可用的计算积木，不能各写重复算法与独立真源。
- **统一读取与检索：** 精确读取回答“现在是什么”，语义召回回答“有什么方法/相关对象”，两者共享身份、条件与来源而不混用。三包提供世界与资产事实，四包接共同检索、双端目录与展开，二包让 AC 直接得到有类型的世界参数，不依赖模型先把环境文字再猜回参数。
- **环境块与地图/资产：** 当前环境、按需专题、长期地点/设施/资源、探索覆盖和真实路线均在本期范围；规划和执行收到相关短目录与新鲜度，按需挂载、展开和卸载。一个箱子样例通过不等于整条资产线完成。

### 0.2 AC 的完整施工范围

沿[053 AC 与积木](<053-轮回训练施工单.md#L129-L170>)、[019 执行契约](<../架构/019-ACX模块.md#L15-L54>)，AC 必须是“**读当前世界 → 计算/筛选 → 条件选择 → 绑定参数 → 调原子动作或子 AC → 核真实结果 → 必要时重观测**”，不是固定工具列表播放器。下列全部属于本工程，可分批但不得漏交：

1. 世界参数直接读取、公共计算调用、变量和结果绑定、条件分支、有界循环与重新观察；现有表达够用就复用，缺口扩原 Loader/Runner/宿主，不另造任意代码执行器。
2. 可参数化查询/计算/导航/交互/采集等积木，输入输出、范围、取消和世界后态真实可验；矿点合法还要核路径合法，未知与零候选分开。
3. 多 AC 同时观察、计算、等待；同身体冲突由原宿主按实际资源、原因和优先级唯一仲裁。等待某个动作不能挡住其他 AC 的独立检测。
4. 异步反馈、必要抢占、断点、重评恢复、取消/迟到回执隔离、工具自身分阶段进展检查与有限自救；身体空出来不等于旧目标和旧路径仍可用。
5. AC 调 AC、带类型输入输出的临时组合、父子归属、固定依赖版本、取消传播及共享预算；不重放已完成或结果未知的副作用。本期由外部 AI 能编写、校验和试用这些组合，游戏内学习者未来框架内编程不作本期前置。
6. 常驻基础、情境浮现、长尾检索、按登记条件自动触发四种入口；实际注册、目录可见、工具可调用、真实执行逐层核，不以脚本在库代签。
7. 逐工具对照真实产出、取消恢复、延时及计算成本；替代有效才隐藏对应旧高层入口，保实现与回退。首批不要求拆尽每个函数，但必须交可复用机制和跨场景消费证据，不能只给几个硬编码动作。

### 0.3 skills 组装、独立使用和三种并行都要交付

按[053 组件与检索](<053-轮回训练施工单.md#L80-L125>)，经验、AC、任务模板、环境专题、基建方法分别走已有登记/校验入口，既能独立找、独立展开、独立使用，也能由场景 skill 按版本引用。包不复制正文，不替各领域执行或判完成。目标与世界共同召回；必需缺失明确不可执行、可选缺失可降级；重复引用去重，撤包只释放自身引用。共享的是来源、身份、适用条件、版本及效果关联，[五类生命周期](<053-轮回训练施工单.md#L172-L184>)各保专属状态，不合成一个大状态机。外置学习者完成查重→写改→试用→实际采用/拒绝与结果复核→修版或撤回，实验工具用于观察游戏里的 AI，不改为监督工程人员。

**三个并行层次分别验：** 四包工程同时开发；主/支/日常逻辑待办交错推进；多个 AC 同时观察/计算/等待而身体只由一个宿主裁决。组件独立可用不等于每个组件都要独占线程，也不等于所有动作能同时做。

### 0.4 结算按完整能力，不按样例数量

指挥官将上述能力逐项映射到四包原派工卡，标明已有可复用、待接线、待实现、待验及真实消费者，记录留原交付账，不新增一套测试平台。先核基线与写权后四包并行，主工边收边接；过夜之后继续用限定矿区采集/并行危险检测/抢占重评、供食、交易及重要损失恢复等验证通用机制。临时组合、统一计算、世界参数直读、场景组装或双端消费尚未兑现时，不得只凭睡眠成功、单测数或几个脚本宣布轮回准备完成。正式通关及跨轮训练仍归 053；准备框架验收不要求预签自然通关。

## 2. 四张派工卡（共享接口只认一个写入方）

### 一组｜任务链、执行 AI 协商与游戏内监督

**交付对象：规划 AI、执行 AI 和 RDD 原任务宿主。** 主/支/日常可并行待办、等待或交错推进。实际发给执行 AI 的请求应能看到各候选为什么现在值得做、优先级、等待/重评时机、资源占用和完成条件；它能按目标和理由找方法，选择先做、暂缓、拒绝、恢复或建议重排。规划可据证据改后续依赖，不固定死流程。执行 AI 可以报机遇、数量、提前满足、受阻和替代意见；有权修改的是本任务自己的判据，涉及别人任务或整条路线要交相应所有者。不能把“灵活”做成谁都能改主线，也不能把“限写”做成执行者只准报成功。见[任务与协商契约](<../架构/027-任务链线.md#L15-L75>)。

- **先接哪一段：** 认领 RDD 任务宿主、主支日常投影、监督判定和上报消费；核规划/执行两端实际消息及工具表和服务端写入口。保留既有十分钟游戏运行时暂停、主人暂停和正常回执；只在确实断链时补催。模型在飞、工具或后台 AC 活跃、有效等待/回执在途不催。二组供活动与终态，一组不接管身体。先对[监督候选与未适配夹具](<054-现实摄影和小补丁补全.md#L39-L49>)，不重写第二个看门狗。
- **死亡及非死亡的重要损失：** 死后先核取并实际穿用可用备用，再按风险、窗口和可达性判断能否捡回；能回收就核实际所得。确实不可收回的部分，再结合原有物品重要度、目标依赖、当前持有和可用替代，让规划 AI 在“原路继续／局部补准备／调整剩余路线”中选择。无备用不是冒险冲回去的命令；未加载、尚未核实、拒冒险不等于物品已永久丢失。**没死也适用重要度判断**，不需伪造死亡事件；普通消耗、存箱、有备用不能触发整链重来。保留有效基地、目标和已完成事实。复用既有损失判断（内部记录未公开），不另定全局件数阈值。
- **验收：** ① 同一执行请求能见多个待办，非冲突提醒不抢动作，合理选择/拒绝有由来。② 支线报草不改主线铁镐，合法自有上调能成，旧代不能改新任务，已在重规划的异议回原请求复核。③ 正常工作不误催、真的断链能接回，分别核实际收件和下一动作，入队不算。④ 用[死后判有备用却仍请求重排的旧例](<[内部路径已省略] Best of Twilight [内部原始日志未公开]>)与“未死但关键能力确失且无替代”对照，核最终改的是正确依赖和完成条件，不只看计划版本变了。

### 二组｜AC 并行检测、优先级与唯一身体执行

**交付对象：正在运行的 AC、执行 AI、原 Numen 身体宿主。** 多个 AC 同时观察、计算或等待；争同一身体资源时才比较优先级、原因和能否等待，由原宿主选一个实际动作。保留现有槽位，不加第二个身体驾驶员。任务型条件由 RDD 登记/去重，ACX 管脚本和 run；目录常驻、情境浮现、长尾检索、自动触发是四种用法，浮现不等于自动执行。见[AC 架构](<../架构/019-ACX模块.md#L15-L55>)、[原子工具与迁移](<../架构/028-Numen引擎与执行层.md#L15-L25>)。

- **先接哪一段：** 复用 Loader/Runner、实际注册积木、宿主桥和唯一仲裁；以 053 的并行红绿对照（内部记录未公开）为起点，不整树覆盖旧 054 的守卫。保原动作身份、run/调用与身体代次、资源、版本、取消断点、迟到回执的归属。重复同动作不重发；普通争用明确等待，不静默掐掉旧动作。
- **本工程后续批次（不得移出本期范围）：** 有依据的紧急动作可抢占，执行 AI 收到原因；危险解除后重新观察任务、位置、装备和目标，决定续跑、换候选或退出。空槽检查不能冒充重新观察。增加可参数化观测/计算/动作积木、异步反馈、固定版本的父子 AC、预算与取消传播；不允许无界递归或重放结果未知的副作用。旧高层工具逐个验证可替代才隐藏，保实现和回退。
- **验收：** ① 一个 AC 等掉落时另一 AC 能观察/计算；相争时只有一个动作执行，撤销旧 run 的回执不能释放新动作。② 采矿用有效路径、目标方块、匹配掉落及实际入包分阶段核；绕障或原地正常挖不误停，来回跑不记采到，部分产出如实结算。自救预算耗尽要释放身体，不由采矿直接叫睡眠。③ 验遇险抢占、危险解除后现场变化、嵌套取消、真正自动触发与同条件不重复；核实际工具在当轮可调用、动作终态、世界后态和成本。脚本在库不等于模型能调用，见054 实例反例（内部记录未公开）。

### 三组｜统一世界源、环境块、长期资产与世界地图

**交付对象：规划、执行、AC 和学习取证对同一对象的读端。** 按[统一数据契约](<../架构/008-WorldState模块.md#L15-L38>)接“生产观测/领域事件 → 增量更新 → 有界计算与可失效缓存 → 环境块/资产地图 → 实际请求”。WorldState 管观测，Settlement 管设施，RDD 管资产事实及对任务的影响；不建全世界库存总账。实验时间线是历史原证，不当实时观测源。

- **先接哪一段：** 选一个可变化的资产（如基地备用箱/炉）和一个短期专题（如床/夜间风险）。观测带世界、会话、主体、范围、覆盖和时间；派生结果带输入修订、算法与参数。新输入覆盖旧结果；过期、断流、跨档同坐标、卸载和真消失分开，迟到结果不冒新值。读取不偷偷全图扫描，有需要才显式有界刷新。
- **长期与常驻：** 按[资产地图](<../架构/014-RDD模块.md#L39-L47>)和[环境专题](<038-主动环境聚焦与同伴轨迹架构方案.md#L101-L139>)，保有用途的地点/设施/资源、取用办法与限制；地图按世界、维度、区域、地点展开，区分探索覆盖、历史已见、当前可用和实际走过的路线。两端常驻的是眼前关键环境与**相关短目录、用途、新鲜度、展开入口**，非全量地图或远方库存。专题可自动或主动挂载，重复引用去重，退出只释放自己的引用。规划看路线和备用，执行看当前风险与取用位置。
- **验收：** 复用已有分页与精确详情（内部记录未公开）及焦点挂卸的历史窄证（内部记录未公开）。同档确认拆炉不能继续算可用，区块未加载不能算已拆，箱子已空与没查到不同；实际走过 A→B 不把 B→A 标成已通。核两端**最终请求及实际展开**；专题换目标、撤回、超预算时应正确消失，安全底线保留。

### 四组｜独立组件、场景 skills、统一检索与外置学习实验工具

**交付对象：组件作者、规划/执行 AI、外置学习者。** 经验、工具积木、AC、任务模板、环境专题、设施使用方法都能单独登记、检索、展开并走原模块调用；场景包按版本引用它们。统一找法和使用归属，不另造万能注册中心/执行器。规划更重路线与依赖，执行更重当前目标、环境、风险与能力；不用先知道名字才能找到。见[053 组件消费](<053-轮回训练施工单.md#L80-L125>)与[学习线](<../架构/026-学习线.md#L61-L73>)。

- **先接哪一段：** 对各类产物核原登记入口、可执行性检查与真实消费者。以独立过夜方法和引用它的场景包作首例：目录给名字、用途、why、条件、版本，按需展开单件/整包；必需能力缺失就明示不能执行，可选项缺失可降级。主树执行侧已有目录入口（内部记录未公开），但旧 054 候选仍直接贡献正文（内部记录未公开），整合时以实际版本为准。
- **生命周期与证据：** 依[053 各对象生命周期](<053-轮回训练施工单.md#L172-L184>)分别处理内容试用/发布/撤回、AC 在飞运行、逻辑任务延期/完成、世界事实过期/重算、专题挂载/共享释放；共同的是身份、适用条件、版本关联和证据，不共用状态机。区分召回原因、方法为什么适用、执行者实际采纳或拒绝的原因。撤回版本不再对新任务召回，不抹历史，不凭撤回文档回滚世界动作。
- **实验工具归谁：** 外部 AI 观察的是**游戏里的 AI**。复用[实验工具登记与证据分工](<../工程/进游戏验证/001-进游戏核心工具.md#L68-L106>)和外置学习者岗位（内部记录未公开）：主动看异常/机会，也接内部学习信号；按同一局关联实际输入、选择理由、工具参数/回执、世界后态及已有可判影像。区分无匹配、索引已旧、没有覆盖；登记不等于当前会话能用，样例调通不等于真实任务有用。需要新探针先查已有入口，不把外部脚本塞入游戏动作表。不纳入监督工程人员的工具，不让外置学习者驾驶；内部以后在框架内编程不挡本期。
- **验收：** 同一组件独立和包内各命中一次，只有一个有效版本、一次应有挂载/实例；有错误条件时能合理拒绝。外置学习者从一个带原件的问题出发，先查重，再写/改一个版本，机器检查→试用→核实际收件、采用/拒绝及世界后态→据证保留、修版或撤回。同步调用按真实调用身份归属，不造身体任务。见[正文已送达但未证自然采用的原例](<046-skills接入检索施工单-20261108.md#L101-L107>)；缺采用就报缺采用，不以看见、动作相似或工具 SUCCESS 代签。

## 3. 指挥官怎么并行派、主工怎么联调

1. **定版本和写权，再同时起步。** 四人各认一包和真实读端，一人兼集成主工，不设第五个协调岗。认领各自产品文件、反例和依赖。共用存档/服务端会话、同伴、任务/代次、对象引用/版本、run/调用与事件时间；只在已有接口缺必要信息时扩展。共享宿主、注册表或发布入口指定一人合，其他人交消费测试，不四人同时改。
2. **不等全组开工。** 一组可回放误催、串写和损失重排；二组可跑争用与非争用；三组可先做箱/炉更新、失效与两端投影；四组可先做目录、包/组件、版本与实验工具的同局取证。尚缺上下游时可用同接口夹具，必须标“离线”，不能算真实接入。谁先交就先验。
3. **明确交什么给谁。** 三→一/二/四：带来源与时效的世界事实及变化；一→二/四：所选任务、why、优先级和允许操作的身份；二→一/四：占用、真实进展、终态、抢占恢复及实际产出；四→一/二：可发现的版本/适用方法，不发身体命令。主工用一次请求贯穿这四段，回执回原 owner，避免两组同时裁决。
4. **055 负责第一次组合：安家过夜。** 从当前世界核夜间/床及未知 → 目录取方法 → 原任务宿主平行保主线、安排睡眠 → AC 观察原动作并有界让位 → 唯一身体裁决 → 服务端确认实睡/醒来 → 恢复原链、原子任务 → 外置学习者回查采用及效果。找到床、绑定重生点、发了提醒、未验的学习稿**都不算过夜成功**；错局床、等正常动作、无床或床不可达的失败路径也要能解释。
5. **再跨场景，才交回 053。** 同版核关键装备丢失（含非死亡）对任务/资产的联动；选供食、交易、采矿遇险恢复等不同条件复核各包承诺，不拿首例代签目录、地图、多 AC 或学习全量完成。未覆盖的支路注明条件/负责人和对交付的影响；关键承诺未证则不签该项。正式通关、跨轮训练和整轮收益仍按[053 §5.5、§9](<053-轮回训练施工单.md#L323-L340>)结算，不在本单偷跑。

## 4. 交付与回退

每组交：准确源码/内容版本、认领文件与实际消费者、旧输入为何失败、新结果与相反输入、接口兼容/撤回办法、缺证和下一接手人。主工在**同一整合版本**复跑关键反例；依原流程分别留源码、离线、构建、安装、加载、世界效果，缺哪层写哪层。真实世界窗口由唯一驾驶员在施工范围允许时处理，本文本身不授权部署/开游戏。回退按受影响的包、内容版本或入口进行，保旧高层工具、历史及原档，不用删库/回档代替修复。各层原证仍留在既有回执和验证卡，本单不是第二份测试流水账。

**一句话交接：** 一组决定该干什么，二组保证能边看边算、但身体只做对的一件事，三组说明世界里现在到底有什么，四组让合适的方法找得到、用过后知道是否有用；055 把四者接在一起验过，再交回 053。
