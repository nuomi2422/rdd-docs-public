# RDD 公开文档与架构图谱

**本仓 rdd-docs-public，阅读分支 main。** 这里放两类东西：一是**可运行的架构图谱与 MCP**，让 AI 按需查模块、关系和决策；二是**脱敏后的现行架构、施工与工程经验正文**。它是私有维护主库的公开投影，不是第二个独立维护真源，也不是外部接手文档。

## Harness 在这套项目里的位置

Harness 是**工程脚手架**，不是游戏本体，也不管角色动作。它负责四件事：写码规范与构建核对、进游戏前后验证与真实效果取证、记录与交接、多 AI 拆分和集成交付。它把“改了代码”和“证明真的有用”分开：编译成功不等于部署，工具回执不等于世界改变，单测通过不等于实机有效。

它的公开实现、工具注册表和上传纪律在 [rdd-harness](https://github.com/nuomi2422/rdd-harness/tree/main)；本仓的 Harness 模块（内部记录未公开） 讲职责边界，进游戏验证（内部记录未公开） 讲判据与取证方法。

## 开发期说明与边界

**项目正在开发期。** 公开这些内容是为了让人和 AI 能**读懂、查证、提问题**，不是邀请外部接手维护，也不承诺响应时限。后续会做适配与协作流程，但当前版本刻意保持轻量，不把外部贡献流程压在这份文档上。

状态一律分开写：设计、源码存在、离线测试、已部署/加载、实际调用、世界效果。没有证据的地方写未验，不把旧日期记录算到当前版本。原始日志、私人会话和内部岗位定义不公开；标为“内部原证未公开”的内容不能假定可复算。
