# 术语表

> 从现有文档扒出的统一叫法；按域分组。定义只写边界，细节回原文。

## 组织与流程

| 术语 | 含义 |
|---|---|
| 主人 | 用户；定范围、决定放行；不做技术仲裁 |
| 驾驶员 | 同一实例的游戏控制/起停与受管发布责任者；不等于全项目只有它能写代码，外部学习者可协调范围内并行施工 |
| 审查者 | 只读复核、指出风险；不改文件、不扩范围 |
| 记录者/汇报者 | 只读观察，产物进记录；不驾驶 |
| 批次 | 一次可独立验收的施工单位（H0–H7、A0–A7 等） |
| 批次卡 | 记录一批目标/结果/缺口的文档 |
| 收口 | 一批结束：不再加防御，缺口留档 |
| 旧债/救债 | 未还的工程债；记在旧债记录，不静默蒸发 |
| 门禁 | 机器可判定的关卡；有 BLOCK/WARN/PASS |
| 入口/出口 | 入口=开始前必须读/过的东西；出口=结束前必须写/验的东西 |
| 指针 | 指向真源的路径/链接，不复制正文 |
| 台账 | 流水账（部署、迁移、债），只追加不改历史 |
| 事实源 | 唯一真源；其余只作镜像/指针 |

## 文档库

| 术语 | 含义 |
|---|---|
| docId | 文档稳定 ID（小写点分）；同一 docId 只能一份 current |
| current/draft/superseded/legacy | 现行/草稿/被取代/历史 |
| front matter | 文档头元数据（docId/kind/status/updatedAt…） |
| catalog | 目录.json，由检查器生成，不手写 |
| 写作规则 | 放哪、怎么编号、时间、指针、唯一事实 |
| 记录 | 每个 AI 一份汇报（日期/时间/数据源） |
| 角色 | 各角色自己的提示词与职责 |

## 发布与状态

| 术语 | 含义 |
|---|---|
| SOURCE/BUILT/DEPLOYED/READY/BEHAVIOR_ACCEPTED | 发布五层证据；上层成功不能自动把下层变绿 |
| HC-RELEASE-01/02/03 | 运行中不写 mods；制品来自冻结输入；各层分别有凭据 |
| STOPPED/RUNNING/UNKNOWN | 实例三态；UNKNOWN 不是停止 |
| 实例锁 | 同一实例同一时刻只允许一个写者 |
| 备份/暂存/journal | 写前备份、同卷暂存、持久意图；失败可恢复 |
| 回滚 | 回到已验证版本；active 指针在部署成功后更新 |
| 假完成/假绿 | 流程 exit 0 或测试绿，但业务没发生 |

## 实验与证据

| 术语 | 含义 |
|---|---|
| GK-1/2/3 | 工程一致性/实验与证据/结算与交接 三门 |
| RUN | 一次可复现实验；有 runId/spec/report |
| OBSERVED/INFERRED/UNKNOWN/BLOCKED | 证据等级；不得混写 |
| 判据冻结 | 先写死通过/失败判据，再改码 |
| PASS/FAIL/UNKNOWN | 结果；UNKNOWN 不得改 PASS |
| 假绿率 | 测试/门禁说绿但实际没验到的比例 |
| 审计门 | 退游戏累计 2 次触发 AUDIT-REQUIRED，PASS 后才 clear |

## 学习线

| 术语 | 含义 |
|---|---|
| 学习样本 | 真实运行产生的样本（不是经验条目） |
| occurrence/fingerprint | 同一样本的一次出现/强弱指纹 |
| Skill（技能学习单位） | 多类学习产物的统一目录/包装概念；版本、展开、交付和效果分别记录，不代表所有产物已接齐，也不等于DSH技能目录 |
| 攻略 | 面向规划者的目标相关学习单位集合，摘要先行、按需展开；完整目标链检索属于意图，须核实现 |
| 复核 | 按程序证据复检（2026-11-07 起不等待人工确认）：打开学习单位后检查是否需要纠正改进，不是“复合执行”；打开不等于有效 |
| 目标指纹/内容指纹 | 前者标识目标或目标链关联，后者标识学习内容版本；不能互换，也不能因有字段就认为参与检索 |
| 统一检索层 | MinimalRetrievalService等公共检索协议；当前仍有直接查询/legacy路径，未全统一 |
| 成熟度 | OBSERVED→ATTEMPTED→VERIFIED→GENERALIZED |
| 采用/展开/执行/效果 | 四种不同证据，不能互相冒充 |
| ATTRIBUTION_CONFLICT | 两次复盘结论冲突，提升复核优先级 |
| 漏斗 | 召回→渲染→保留→送达→采用→执行→效果的账本 |

## 自编译/发布链

| 术语 | 含义 |
|---|---|
| mutation | 一次候选变更的完整工作区与生命周期 |
| NumenTool | Numen 可注册的游戏内工具 |
| candidate | 候选制品；具体资格按当前发布模块，不沿用停用ArtifactStore流程 |
| Promotion Gate | 历史设计用语；当前发布按源码/构建/部署/READY/行为证据分别核对 |
| DELIVERED/STOP_LOSS | 历史内部流程状态名，不代表当前外部脚本已采用同一状态机 |
| run-mutation | 编译→部署→启动→MCP→取证→收尾的唯一通道 |

## 游戏/任务链

| 术语 | 含义 |
|---|---|
| RDD/Numen | 任务链驱动/游戏内同伴框架 |
| 同伴 | 游戏内被驱动的 AI 身体 |
| Stage-A/Stage-B | 一级规划/懒展开二级 |
| primary/subtask | 一级目标/二级步骤 |
| wait_for | 步骤前置条件；不得自依赖死锁 |
| acquire/hold | 增量判据/持有判据；acquire 必须先拍基线 |
| RL-1..RL-18 | 不可回退红线（单驾驶员、依赖门、风险门等） |
| 三档任务模型 | 历史分级用语（工具/模块/架构级）；不作为当前固定模型审批或只升不降规则 |
| 九步流 | 分类→查消费者→补测试→埋点→实机→commit→证据→维护说明→不回退 |

## Harness/Agene

| 术语 | 含义 |
|---|---|
| registry | 工具/规范/门禁/时间锁/文档编号的唯一注册表 |
| preflight/postflight | 进游戏前/退游戏后的门禁 |
| bench | 实验台：环境文件+共享账本+冻结判据裁判 |

| 上游/下游 | 表现/认知/模型 provider；下游模块适配 |
