# TLM联动：现有外观插件与MaidSoulCore特殊复合体

> **结论：RDD＋Numen原组合不拆，MSC＋车万女仆原组合保留；可独立、并存、逐能力左右选配。固定女仆主讲只是可选预设，不是全局限制。**
> 名称：车万女仆（Touhou Little Maid，TLM）；灵魂核心（MaidSoulCore，MSC）。
> 前三节为既有外观插件；§4起为2026-11-10人类提出的特殊联动及AI建议设计；23:34后已写纯核心，生产适配未接，最新状态见§12。稳定文档身份仍为 `module.tlm`，不另建同义架构正文。施工唯一入口见[052分阶段施工方案](<../施工/052-女仆与RDD特殊联动施工方案-20261110.md>)。

## 1. 既有外观插件：职责与入口

NumenTlm.java（内部记录未公开）由Builtin在目标模组存在后install；在onClient注册模型列表与穿戴工具，绑定Wardrobe，贡献MaidLook状态，并挂受伤/死亡声音、渲染与退出清理。

## 2. 既有外观插件：数据和边界

Wardrobe保存外观选择，模型资源归客户端/目标模组；渲染状态不是同伴真实装备槽，穿上女仆外观不等于穿防具。工具/声音回调不决定任务链完成，也不拥有学习发布权。

## 3. 既有外观插件：失败与验证

直接引用目标模组类，缺依赖必须避免加载；退出清理由MaidBody.forget处理。外观资源失败不得冒充身体消失或任务终态。本轮只核接线，未验证目标模组版本矩阵。外部编码线维护兼容；学习/任务线仅按需要消费可选展示能力。

## 4. 特殊联动的确认意图与范围（2026-11-10）

**直接人类来源**：本会话 `[会话标识已省略]-b5b9-4116-91d6-6d34d53b21e2` 中，主人介绍合作者的MaidSoulCore与车万女仆生态，要求先列双方能力表、写架构和施工细节，在干活前解释更好的方案。登记决定 **D-20261110-003**，在[034宏观导航](<034-架构思维导航MCP.md>)及035图谱（内部记录未公开）统一投影；不改变四线或三层团队，不借此抢占在飞任务。

### 4.1 已确认的产品意图

- **各取所长而不是替代一方**：保留女仆真实实体、背包、原生工作及附属模组生态，利用RDD的玩家式执行、长程运行、感知、经验和世界资产信息。主人已实际玩过合作者模组，认为陪伴互动很好；本轮不将主观体验改写成量化优劣结论。
- **两个独立AI，相互交流，能力可选配**：RDD保留与Numen的执行适配；玩家可选择聊天、人设、记忆、情感、语音与执行的提供者。仅选择“陪伴代言”预设时，陪伴主讲、RDD静默且保内部证据；不永久剥夺RDD原生交流。
- **统一管理但可按性质选择**：联动核心管理能力借用、覆盖、增强和选择，防并发、防双驾驶；尽量解耦且可拆卸。用户把“一个实体”纠正为“并行实体”，最终物理呈现没有定死。

### 4.1.1 用户澄清：保留原生组合，逐能力左右选配（D-20261110-004）

每项配置区分 enabled、provider、targetBody/outputEntity、mode、policyRevision、数据档案归属与兼容状态。原生模式允许另一侧身份为空，不用伪造maidId/soulId或workerId来凑协议；只有跨侧操作要求完整绑定。换提供者不自动搬人格/记忆，停用只撤销相关能力，不停无关执行、不删实体或背包。应用前核依赖与冲突，排空相关在飞动作/语音，原子切配置版本，迟到输出拒收；失败保留原策略并显示原因。

“自由选配”指产品目标，不是所有组合已实现。未支持组合明确禁用并解释缺哪个适配，不能静默切回别的身体。预设＋高级逐项开关是界面建议，非主人指定具体界面。

### 4.2 本文的工程建议，不冒充用户逐项指定

工程建议是**保留两个原生组合，以小型联动控制层提供单开、并存和交叉选配**；玩家不必每次同时生成/启用两个实体。女仆保留原本身体，RDD保留Numen玩家身体；统一能力绑定、共享读取、任务委托和按模式选定的发言出口。不是把两个实体改成同一UUID，也不是共享一份背包/生命/存档。

理由：RDD的NumenPlayer:19–36（内部记录未公开）继承服务端玩家；合作者依赖真实EntityMaid及其底座生态。伪装成同一实体、实时镜像背包、每刻传送叠身体，会损害事件、主人权限、维度、死亡掉落及第三方适配。玩家动作接口并不能不加适配地用在女仆上。

| 方案 | 得到什么 | 代价与选择 |
|---|---|---|
| 双真实实体＋任务委托（可选并存预设） | 双方身体优势和生态都保留；女仆向RDD派意图，RDD自己规划执行 | 世界中是两个身体，工作位置/背包分别说明；风险最低，先验此路 |
| 同一女仆身体按能力交接控制（后续候选） | 女仆表现更统一，部分动作可选提供者 | 必须补女仆身体适配及所有自主行为的暂停/撤销/恢复；不保证所有玩家能力可移植 |
| 单可见主体＋隐藏执行体（暂不采用） | 视觉上像一个角色 | 不可让不可见玩家偷偷跨地操作、复制状态或绕过距离；呈现、掉落、受伤与作弊边界需另定 |
| 强行继承/合并两套脑和存储（不建议） | 表面接口少 | 耦合最大，升级、许可、存档和故障面不可控，不符合本次解耦目的 |

这是一项特殊联动，不要求抽空重写两边所有模块，也不把Agene/Soulbridge、架构导航服务或新模型调度器设为游戏动作的必经依赖。以后能换适配器，但先把这一个组合做实。

这里的“按身体/资源单一控制者”是拟议游戏内运行契约；工程侧仍保持同一实例唯一实验驾驶/部署负责人。两身体逻辑并行不授权两个外部施工窗口同时操作生产实例，也不绕开已有单驾驶纪律。

## 6. 最小核心：管理边界，不重建业务

以下名字均为**拟议职责**，不是已存在的模块或已安装接口。

```text
主人文字/语音 ──输入去重/明确绑定──> 当前选定对话提供者（原生或跨侧）
                                      │ 任务意图/信息请求
                                      ▼
                     联动核心：身份、权限、能力路由、控制权、消息/回执
                        │                         │
             RDD适配器（委托/查询）      女仆适配器（查询/互动/发言）
                        │                         │
           RDD执行AI → Numen玩家身体      MSC/TLM → 女仆真实身体
                        └── 带证据的进度/终态 ──> 当前选定出口（可选陪伴转述）
                        └── 世界/经验/资产只读视图 ──> 按需共享
```

1. **身份与策略**：保存组合绑定、启用能力、提供者版本与选择，不持有领域真源。绑定至少区分服务器/世界/主人、女仆UUID与soulId、RDD同伴UUID、连接世代；两个UUID不可互换。重新绑定需校主人归属与在飞事务。
2. **能力目录和路由**：描述输入/输出版本、依赖、作用对象、读/刷新/写、授权范围、冲突资源、可取消性及终态定义。未知能力默认不接入；公开Java方法不自动等于稳定扩展接口。
3. **控制权与生命周期**：在真实副作用落点校验单一权属，负责撤销、旧代隔离、交接与恢复。不要在模型提示词里实现锁。
4. **消息与发言出口**：传类型化请求/证据状态，去重、限流、取消、重连补偿；按模式输出/转述，不偷取RDD内置脑收件箱。这里只保存有界关联账和必要恢复信息，不复制聊天/任务全史。
5. **适配器与只读视图**：RDD、MSC、TLM底座、心契、更多动作各守自己的线程/版本边界。先通过已有接口接入；缺挂载/暂停接口时与合作者补小型公开钩子，而不是依赖反编译私有字段或把实现全搬进核心。

**可选择性质的语义**：

| 模式 | 含义 | 安全限制/例子 |
|---|---|---|
| 原生 | 不经联动替代本能力 | 关闭联动后各自独立；先确认无未结事务，不突然重启两套驾驶 |
| 只读借用 | 查询另一方已有信息 | 读观测/检索≠刷新世界≠获得使用/搬运权限 |
| 委托 | 请另一方在其原身体完成目标 | 陪伴请RDD采集，结果带实际物资位置；不假装女仆自己完成 |
| 覆盖 | 某能力唯一提供者切换 | 比如在陪伴代言预设中发言由陪伴负责；身体类先证明旧提供者真停，再启用新方 |
| 增强 | 原提供者执行前获得另一方信息/建议 | 女仆陪伴借RDD危险/资产信息；建议不能直接变成第二动作写者 |
| 禁用 | 明确关闭某项联动能力 | 不能顺带关闭安全闸或删原数据；依赖缺失返回不可用，不静默换陌生提供者 |

策略按能力、对象和绑定范围版本化；变更先算影响与冲突，再排空/取消相关动作，切代次后应用。运行中不能只改UI开关就宣称完成切换。

## 7. 防双驾驶：排他的是副作用，不是思考

**设计不变量（2026-11-10，原因：多个原生循环和异步回调会绕过顶层锁；例：跟随/工作与RDD移动同时控制或超时动作晚到）：**

- 两脑可同时内部交流、思考、读信息，面向用户按会话/实体选择发言者，并存可各自交流但同一输入不得无意双答；同一身体的冲突动作只能一个控制者。首版保守用“整身体动作租约”，不要先把移动/转头/手臂拆成大量可组合锁；纯表情以后证明无冲突再放行。
- 动作权是**有期限的授权＋单调递增代次**，不是布尔忙闲。请求含组合/身体/世界/会话/调用者/代次/任务/资源/期限；字段必须由可信适配器验证，不能由模型自称。撤销后旧代回调不得启动新副作用或改变新代任务状态；已发生的副作用与迟到终态仍保留原身份进入审计/对账，不能一丢了之。
- 女仆原生导航、工作、拾取、自动战斗、坐站、心契工作/互动、更多动作、手动控制入口；RDD长任务、同步短动作、反射、安全与外部直接调用，都须查覆盖。不受控写者存在时该能力不开放“覆盖”，只能原生或独立身体委托。
- 跨身体/容器的互动按全部受影响资源预留，按统一顺序获取，失败即释放，避免死锁与重复消费。背包只允许各自所有者真实读写，不复制ItemStack或用坐标传送模拟成功。
- 安全层优先于普通任务；紧急撤销不等模型同意，但安全动作也要进入明确所有权关系。安全STOP与普通让路区分：停止新的自主工作不等于禁用一切保命动作。受控实验确认现有反射如何参与，不再造一个互抢的安全脑。

**推荐交接状态**：原生/已授予 → 撤销请求 → 排空与确认已停止 → 提升代次 → 新控制者已授予。任何一步身份不明、超时或停机证据不足，进入安全等待/隔离，不把“取消请求已受理”当“已经停下”。

每个世界会话只有一个权威仲裁者，实际身体副作用由所属服务端强制执行；两个客户端/两脑不能各持一把“我有效”的本地锁。重启必须使用新的不可混淆会话身份并失效旧许可，租约到期只表示不能继续授权，不证明动作已停/物品已回滚。不能在权威不可达时让另一侧自行发新许可；是否分进程不改变此约束。

## 8. 按模式选择主讲与两脑交流

- **输出隔离到实际出口**：按所选模式路由/启停RDD常规回复、气泡、语音、自动声音及MSC/TLM聊天。只有陪伴代言预设要求RDD静默；原生并存允许各实体保留自己选定的对话入口。不能只在提示词说“不要讲话”。是否保留非语言受伤音效作为体验选项，单列开关，不暗中恢复当前已关闭的发言提供者。原版游戏死亡通知/管理诊断不伪装成陪伴聊天。
- **静默不等于失联**：内部结构化状态、危险、失败、审计继续。当前选定的转述者拿到“受理/进行/失败/取消/完成/未知”后转述；成功、数量、物品位置、因果归属只能依据原回执与当前事实。自然语言可温柔，但不能把“找到了箱子”讲成“已经拿到物品”。无法可靠转述时用当前选定输出通道的固定事实模板，不让模型猜。
- **输入一次投递**：语音识别、文字和快捷命令共享requestId去重；明确绑定主人、目标会话/实体及所选提供者，不因“附近最近女仆”自动串到别的组合。紧急停止由可信输入独立触发安全处理，不依赖陪伴模型生成转述；是否额外展示非人格系统故障通知列为体验待确认。
- **内部交流不是互相模拟主人**：消息有来源类型、会话/世界身份、关联任务、意图/证据/疑问/建议之分。陪伴提出的请求不是主人最高权限命令，普通聊天不自动重写主线；双方可问条件/拒绝/协商，不允许互相转发语音文本造成无限聊天循环。设有界队列、因果去重与回合预算，具体阈值实测后定。
- **回执语义**：受理不等于开始，开始不等于完成，工具终态不等于目标硬核验。超时而副作用可能发生时返回UNKNOWN并查询对账，不能自动重试搬运/攻击/生成操作。取消同样要终态与旧回调隔离证据。
- **委托不抢主人目标**：在任务权威侧按当前goalId/planRevision/stateVersion原子检查并受理非抢占请求；忙时明确拒绝或进入既有协商，不直接借主人级替换入口清旧目标。取消仅作用于本binding/request绑定的任务及代次，过期取消不得停掉后来主人目标。现有RddPlugin:288–308（内部记录未公开）的GoalSinks会replace或按UUID清理，beginPlanning:498–516（内部记录未公开）会丢弃旧目标，因此“可复用规划内部逻辑”不等于“入口已经具备安全低权限委托”。

可复用但不足：RDD NumenGateway回执:95–105（内部记录未公开）带身份但明确accepted≠effective；NumenActuator:168–245（内部记录未公开）事件是消费式take、say是直接输出，不能让两个AI抢同一收件箱或旁路发言。MSC已有语音队列与中断（内部源码/原件未公开），但随包说明:17–19（内部源码/原件未公开）明确TLM原聊天独立，仍需跨出口覆盖证明。

## 9. 共享知识与安全边界
