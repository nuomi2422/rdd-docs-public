# 写代码规范

> 稳定指纹：`rdd-harness.write.v1`；用途：修改源码、接口、构建或部署时展开。先读本页，再按实际任务取子文件；不要把四份指针全文和整仓规范一起常驻。

改 RDD 代码时，找准模块边界、世界数据来源和验证办法。

**代码该放哪。** [RDD 领域核与宿主](<014-RDD模块.md>)区分不依赖 Minecraft、LLM 的纯 Java 核与宿主接线；[Numen 执行与适配](<028-Numen引擎与执行层.md>)说明工具、身体和加载器的职责。涉及世界事实，查[WorldState](<008-WorldState模块.md>)的来源、时效及领域写权，避免同一事实另采一份。

**怎么改、怎么验。** 写码和提交无需门禁。 工程纪律（内部记录未公开）管当前工作区、构建部署和并行改动；编程规范（内部记录未公开）按条目查具体做法。改接口先找使用它的代码，再用能区分改前改后的测试验证。

**要证明运行效果时。** [发布契约](<002-发布契约.md>)核对源码、制品与目标实例；世界行为是否改善，接[进游戏验证](<038-进游戏验证指针.md>)。
