# ACX：动作脚本执行与版本生命周期

## AC执行层目标（2026-11-17，D-20261117-EXEC-001）

在既有ACX上补原子积木组合、实时数据消费和并行调度；保Loader/Runner、权威目录、版本库及真实回执，逐项重整Numen行为实现。此为设计契约，当前实施批次与授权边界只见[053 §0/§6](<../施工/053-轮回训练施工单.md>)，不预签完整实现或实机有效；执行底座迁移边界见[028](<028-Numen引擎与执行层.md>)，数据链路只见[008](<008-WorldState模块.md>)。

### 目录有四种使用方式

常驻基础能力供随时调用；情境浮现能力随昼夜/农事/敌情等出现并在不适用时退出；长尾能力通过统一检索展开；自动AC按已登记触发条件反应。同一AC可支持多种方式，身份和版本只有一份。**浮现目录不等于自动执行**，**自动触发分工（053 第二批实施决定，非新增主人规则）：** 任务型条件登记、触发去重和失效归 RDD 现有 `SideTaskHost`/引擎，沿[任务链日常契约](<027-任务链线.md#L15-L23>)；ACX 仍拥有脚本活动版本、检查与执行。先让任务宿主用现有只读能力取精确活动版本，再用现有日常机制验证一次提醒的实际消费，不调用工具表来绕过执行边界。真正的自动执行另接原受权调度与单身体仲裁，未接不签运行。观测要核当前世界、服务端会话、同伴、代次及时效；不能把维度名当存档身份，也不能由情境目录或旧版本自动触发。

### 并行、抢占、异步与嵌套

- 多个run可以同时存活、计算、观察、等待；身体动作按实际资源互斥和优先级仲裁。无法证明可同时执行的身体动作先沿现单赢家路径，不以多线程冒并行能力。
- 挖矿遇袭：保存采矿状态→依据当前装备、补给、状态和敌情计算战/逃→抢占必要动作资源→防御或撤离→危险解除后重新读取位置、目标矿点和约束→恢复或重新规划。中断不是失败完成，恢复不能盲用原路径。
- 异步受理保run与调用身份；自动防御期间，执行AI可获中断原因、当前状态和恢复结果，不必靠反复轮询才能知道发生了什么。AI能预备有类型参数的临时组合，待条件满足交同一执行宿主运行。
- AC可引用/调用AC；固定依赖版本和父子run关系，取消、资源占用、错误与恢复可追到父调用。嵌套组合先做无环引用及有界深度/预算；不把现HostBridge拒递归门面直接取消而制造无限自调用。原子粒度以可独立使用、参数可调、结果可验为准，不机械拆每个内部函数。

### 工具自身检查效果

**异步工具接下任务后，自己持续检查是否在取得有效进展，并承担本工具范围内的有限恢复。** 这是主人原文“工具自己带效应”的要求；只返回RUNNING后等模型主动发现空转不符合目标。以下是对原要求的实现细化（授权范围内AI决策），先复用现有工具检测、调度与反馈机制，缺哪项补哪项，不另起全局看门狗。

| 动作 | 能算进展的观测 | 不能单独作为进展/成功的信号 |
|---|---|---|
| 导航 | 有效路径段推进、接近当前可达子目标、越过障碍或到达判据 | 心跳刷新、反复重算同一路、原地抖动或来回绕圈；绕障暂时远离终点不应直接判卡死 |
| 采矿/收集 | 目标方块真实变化、掉落状态、目标物品实际拾取，按当前阶段分别检查 | 挥手、调用受理、只破坏未拾取；破坏块数不等于入包件数，产量核规则、消耗及外部介入 |
| 战斗 | 有效接近/取得视线、可归属的命中/伤害、击退/脱险或目标阶段变化 | 不断攻击空气、目标消失就宣布击杀；有攻击动画不等于造成有效伤害 |

1. **启动时立进展基准。** 绑定run、调用、同伴/世界/身体代次、目标与参数，保存当前阶段、最后有效进展及观测来源/时间；返回可查询的运行身份。工具声明预期效果、可接受等待和恢复预算，不能只给一个无归属的后台任务。
2. **按阶段判断，不按一个超时秒数套全部工具。** 观察/动作执行/等冷却/等资源/被抢占各有判据；合法等待需有原因、唤醒条件和下次复查或上限。等待农作物成熟交轻量日常任务，不让身体工具占槽空等；等待缺数据与确认无进展分开，旧缓存、重复心跳和模型自述不刷新“有效进展”。
3. **检测随工具执行，复用同源观测。** 用已有游戏事件、增量与有界周期检查，不让每个AC每tick各扫全世界。以有效采样和动作机会判断停滞；抢占/暂停时间不算该工具的动作空转，同时总等待仍受任务预算约束。采样断流记观测未知，不能冒充正常推进或确认失败。频率、阈值和容差按动作/阶段配置并验证，不在文档拍固定数字。
4. **局部恢复有边界。** 先重观测确认目标/条件，再选择本工具允许的重寻路、换合法候选、调整可达交互点或补拾取。每次恢复保原因、实际动作和效果；重复同一无效动作、换子调用或重置阶段不能刷新整个重试预算。耗尽预算、条件不成立或存在不可判副作用时结束/挂起并交上层处理，不能无限自救，也不能自行扩大开挖范围或改总目标。
5. **异步反馈既可推送，也可回查。** 沿现有事件/反馈路径发送重要阶段变化、被抢占、局部恢复、阻塞与终态，附当前进展、最后有效观测、原因和已尝试办法。普通进展可合并/限频，终态与需决策的阻塞不能被合并丢失；状态查询可读同一份最新记录，避免模型只能频繁轮询。发出事件不等于AI实际收到，按真实消费者验送达。
6. **抢占后先重新判断再续。** 保存可恢复的逻辑位置与已确认副作用，释放被抢占资源；防御结束后核位置、目标、装备/补给、任务代次和原参数约束，再继续、重选或上报重规划。不盲续旧路径、不重做已完成的不可重复动作。紧急性按当前风险与资源需要判定，防抖和公平性按原调度扩展，不把所有run一起停止。
7. **结束和取消要闭合。** 受理、局部进展、完成、失败、取消、结果未知是不同语义，映射原状态而非强造新枚举。取消请求进入原宿主，停止新增动作并收回本run持有的资源/订阅；收到取消请求不等于身体已经停止，已发生的世界影响不自动回滚。终态按该次身份只结算一次，迟到成功不能覆盖取消/失败；超时后副作用不明如实保未知。
8. **嵌套与并行保各自归属。** 父AC等待子AC时检查子run的实际进展与终态，不把“子run还活着”当业务推进；父取消传播到其拥有的子运行，不能误停别的引用者。各run保定义/依赖版本、结果和资源归属，旧回调不得串给新run；资源互斥仍由唯一身体仲裁。
9. **参数变化也要有生效边界。** 范围、高度、筛选、路径风险、自动寻路与预算等按真实能力显式声明。启动前校验；运行中可调整哪些项、何时生效由工具契约说明，需要重规划/重启的就明确返回，不能静默忽略或在一个动作中途混用两套约束。临时组合和AC套AC同样适用。

工具检测证明本次动作的进展或异常；跨样本原因分析、评价修订和改版由学习者承担；RDD目标完成仍依据任务世界判据。三者相互引用证据，不能用工具自己的SUCCESS或评分包办全部验证。

## 轮回训练扩展契约（2026-11-15主人直接要求）

AC面向“当前观测→有界算法计算/筛选→条件选择→积木调用→真实结果”，既可自动判定执行，也用于减少模型重复决策。世界观测沿原WorldState/领域接口读取，计算保输入来源，身体动作沿原Numen调度；具体范围、时效、取消和结果不能由脚本SUCCESS代签。现成工具可按可独立使用的输入/输出拆为积木，保高层兼容入口，复用AcxBlockCatalog/HostBridge/Loader/Runner与版本库，不另造通用执行框架。

训练产生的AC按用途分类、分基础积木/复用脚本层级管理，重要且适用的能力在前，长尾由统一检索或AI主动搜索展开。AC可单独用，也可被场景skill引用；包不会取得身体或观测写权。当前外部AI编写，后续内部AI借权威目录和模板临时组合，同样校验并有界执行；新run用新版本，在飞run不静默换定义。

本段为D-20261115-001设计，未核成所有算法/组合能力已实现；代码复用、外部源码适配、矿点与路径范围反控及迁移回退见[053 §4](<../施工/053-轮回训练施工单.md>)。下面旧核验记录保原时点，不作为今天全部未修的断言。

### 恢复时如何判定能否再派发（053 LH2b，授权范围内AI决策）

一次身体调用沿原 run、结构调用位置、原身体代次及已解析参数结算。**是否允许再派发，由宿主能证明什么决定**；请求等待结束只说明调用方不再等。用现有会话、调用记录和宿主线程门传递以下区别，不靠解析异常文案。

| 宿主对原调用能证明的事实 | 同一 run 恢复时的动作 | 可判定的反例 |
|---|---|---|
| 在进入工具前已取消，且排队闭包已失去执行权 | 保留可恢复断点；显式恢复并复核原身份后才派发 | 手动放行旧闭包时身体调用仍为 0；恢复后累计为 1 |
| 工具可能已执行，但回复丢失、超时或受理号未知 | 保留原调用未决标记；只查原调用，不能因无 taskId、等待预算耗尽或旧断点重放而再派发。无法取证可结束等待并交重规划，不能推断动作没发生 | 交易已扣款而回信迟到：恢复前后扣款合计 1 次。迟到证据只更新原调用事实，不复活已终止的 run |
| 原调用已获确定结果 | 恢复用原结果；在所属帧提交消费进度后才释放对应回执 | 子脚本第一步已经完成、第二步才暂停，恢复不重做第一步，也不提前推进父断点 |

同一调用不能把补传的新目标或参数套到旧回执上；需改变已派发动作的对象或数量时，先结算原调用，再按新意图重规划。身体暂时不可见只记未知；确认原实体被替换或宿主卸载后，关闭该代次的恢复入口，释放实体强引用和订阅，保留能解释未决副作用的最小记录。旧断点不能接到同 UUID 的新实体。无法保住调用身份和回执的旧记录只供查询，不宣称跨重启可安全续跑。

**子脚本的实际绑定也属于断点。** 首次解析保存用的是子 AC 还是原子工具，以及对应定义身份；同一 run 按原依赖版本继续。版本库切换 active 只影响新 run 的选择；已进入的子调用若找不到原定义、内容指纹不符或同名项类型改变，应在派发替代动作前拒绝，仍允许回查原任务。新 run 的顶层与嵌套调用依同一发布规则取版本，旧入口可保留为兼容解析器，不另建版本库。

源码依据（静态，非实机）：联合候选 `5a16cde00` 的 宿主桥（内部记录未公开） 在工具调用异常或等回信超时时均可返回 FAILED；该结果本身不足以证明未派发。A 候选 `0e723f425` 的 宿主装配（内部记录未公开） 给 Runner 接启动目录，门面另接版本库；子调用解析（内部记录未公开） 只在找到子定义时比指纹。验收须分两种变更：只切发布指针，旧 run 仍消费 A 的原回执、新 run 按新发布选择 B；让原定义确实不可得且放入同名工具，替代工具调用数为 0。只替换测试目录不能证明生产发布接线。若新解析入口回退，先恢复原入口供新 run 使用，未决旧 run 仍按原身份查询或拒绝续跑。
