# RDD：任务进度、规划适配与恢复

## 分层与所有权

rdd-core是无Minecraft/LLM依赖的领域层；TaskChain持有Goal→Primary→Subtask进度、状态、attempt、基线、planRevision、stateVersion和执行身份。plugins:rdd是宿主适配，负责规划调用、世界事实核验、监督、重规划与死亡/睡眠支线接线。不能把纯核边界误写成“整个RDD不管规划/死亡恢复”。

## 入口与数据

RddPlugin.java（内部记录未公开）注册submit/restart/status/patch等入口，装配SideTaskHost并按同伴保存rdd-tasks/assets/facts/history/ledger等数据。

| 状态 | 所有者 | 不能替代 |
|---|---|---|
| 任务进度与代次 | TaskChain | 世界当前准备状态 |
| 可复用资产 | AssetRegistry | Settlement设施登记或全世界实时库存 |
| 完成历史与辅助留档 | CompletedFactStore | 当前穿戴/指定箱内存货 |
| 死亡批次 | RddDeathLedger | 掉落已找回的证据 |
| 身体任务终态 | Numen引擎 | RDD业务目标达成 |

## 生产链路与契约

Stage-A规划一级→Stage-B懒展开→Detector核验/推进→状态与事实记录；宿主连接模型，但模型自述不是完成判据。RDD也直接读服务端世界事实，并非只读WorldState缓存。

执行受理不等于完成；hold/acquire、制作历史、实际穿戴、存箱和成就各有作用域。历史完成可用于有限继承，不证明死亡/重启后物资仍存在。resetForRestart已接线，不能再称死代码。

恢复时RUNNING/STALLED转RECOVERING并失效执行身份；迟到回执需匹配代次/执行身份。坏条目留诊断并按同伴隔离恢复，不能默默整仓清空。bodySubmissionEnabled默认false、supervisionEnabled默认true是策略默认，不是“没有派工能力”。

## 沉淀资产线的现行入口（2026-11-10，经指挥官转述主人）

四线中的沉淀资产线回答超长运行积累的“已有何物、在哪里”：资产库、世界地图、基建、背包、遗迹、机器、基地、群系等均可按需索引和懒加载，保留世界/维度/来源/观测时间、可验证状态和未知。历史已见不等于现在可用、未加载不等于消失、发现不等于已取得；当前行动仍需运行时核验。它不同于学习线的“怎么做/为什么”，也不是新建全世界库存真源。

本节为跨模块资产线的唯一导航正文，复用本模块AssetRegistry/事实投影、[Settlement设施登记](<007-Settlement模块.md>)及[WorldState观测](<008-WorldState模块.md>)等各自权威来源，地图/群系等具体消费者尚需按现状核验，不迁移既有写权。规划和运行按需要展开，不全量灌入；失效/过期/缺身份显式UNKNOWN。原因/案例：主人2026-11-10将长期资产积累独立为第四线，以避免把资产事实混成学习经验。本轮是宏观分类与意图，不宣称全部覆盖、已部署或效果验证。

**2026-11-13语义与双端消费澄清（D-20261113-001）**：资产不是把看见的一切都记成坐标清单。选择有后续用途、与目标或长期能力有关的对象，记录“是什么、在哪里、当前有什么/是否可用、能解决什么需求、怎样取用及限制”，用途可以引用相关skills，实例状态仍归资产/世界事实。例：基地箱不仅是某坐标的箱子，还可说明是恢复用备用装备/食物来源；交易设施保留职业、工作站及可用交易等已有观测和缺口，不能从名字推定功能齐全。具体保留/淘汰策略是实现细化，不要求主人逐个条目决定。

世界语义地图可按世界→维度→区域→地点/设施逐层展开，区分已探索、未知、历史已见、当前可用及路线条件；记录探索覆盖不假装知道未探索地区。规划AI与执行AI都拿到与任务相关的简短资产/地图目录、用途和新鲜度，再主动展开库存、设施、路线等细节。当前环境摘要负责眼前状态，远方长期资产懒加载；两者同源引用但不互相冒充。原因/案例：主人深夜强调“有什么、怎么用、哪里探索过”与两端可见，纠正把沉淀线缩成库存堆积的误解；目前按ID展开、语义使用与规划响应是否已完整接线仍待逐消费者验证。
