# 四包并行的轮回准备框架

> 公开施工范围摘要；来源主题055。四包是同一工程的分工，不新增四个管理层；完整交付仍待真实接线和组合验收。

1. **任务/监督**：多待办及why进入实际请求，自主协商、主支写权、重要损失重规划、正常接续与断链兜底。
2. **AC/执行**：世界参数直读、公共计算、变量/分支/有界循环、原子积木、临时组合/嵌套、并行观察、异步抢占恢复与真实进展。
3. **世界/环境/资产**：增量获取、原始与派生存储、计算缓存和失效、统一读端、长期语义地图、双端目录及专题挂卸。
4. **学习/组装/实验工具**：各类组件独立注册使用或场景组合，统一检索、不同生命周期、试用后复核，以及外部观察游戏AI所需证据入口。

先核基线、认领文件和共同身份，独立模块可同时开发与验收，谁先交谁先接；有依赖先用明确接口夹具但只签离线。主工集成共享接缝，不让多组同时拥有同一写入点。

首个组合例是安家过夜：当前床与时间事实 → 相关方法 → 睡眠待办与保主线 → 原动作有界让位 → 唯一身体裁决 → 服务端实睡/醒来 → 原任务恢复 → 学习核实际采用及结果。绑重生点、找到床、提示入队均不算睡着。

它不是总范围上限。继续以限定区域采矿、并行危险检测及抢占后重评、供食、交易、重要损失恢复核通用性。参数直读、公共计算、组件组装或双端消费没兑现，不能凭过一夜、测试数或脚本数宣布框架完成。正式通关回轮回总目标，不预签。
